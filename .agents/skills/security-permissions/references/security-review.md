## 1. 审查输入

开始前收集：

- 要保护的资产和敏感级别；
- 用户、窗口、Command、插件、远端服务等主体；
- 数据从哪里进入、在哪里校验、保存和输出；
- 会产生哪些本地/远端副作用；
- 用户已授权的动作、目标和时间范围；
- 失败与撤销能否恢复。

把 WebView、IPC 参数、导入文件、剪贴板、URL、SSH/数据库响应和插件事件都视为不可信输入。前端校验只改善体验，Rust 信任边界仍须验证。

## 2. 凭据与秘密

- 密码、Token、SSH/签名私钥、数据库口令只存入 Safe Credentials、系统 Keychain 或 CI Secrets。
- 前端只传安全凭据引用/ID，不返回秘密原文；Rust Service 负责在最短生命周期解析和使用。
- 禁止把秘密写入源码、`.env` 示例、命令参数、进程列表、日志、截图、错误、测试夹具、SQLite 普通字段或 updater manifest。
- 不通过 Shell 凭据助手把 PAT 提取进变量或模型上下文；使用 Tauri SSH MCP/受控 Connector。
- 轮换、删除或覆盖凭据是外部安全状态变更，必须明确授权并保留审计证据。
- 备份签名密钥时使用受控加密存储；丢失密钥的恢复方案必须在发布前确认。

## 3. 外部输入与命令

对每个输入定义类型、长度、字符集、枚举、路径根、URL scheme/host、数量和超时上限。

- Shell：优先参数化进程 API，禁止字符串拼接、`sh -c`、`eval` 和用户可控命令名。
- 路径：规范化后确认仍位于允许根目录；拒绝 `..`、符号链接逃逸和设备路径。
- JSON：使用明确结构反序列化，拒绝未知危险字段，限制嵌套和载荷大小。
- URL：只允许业务需要的 HTTPS host/port/path；阻止 loopback、link-local、metadata 和重定向逃逸。
- 远端输出：不直接拼 SQL、Shell、HTML 或路径；保留编码和长度限制。

Command 应返回显式 `Result`，错误可诊断但不包含秘密。禁止 `unwrap()`、`panic!()` 和静默安全降级。

## 4. CSP 与外部 URL

CSP 从最小基线开始，只开放真实使用的 source。不要用通配 `*`、`unsafe-eval` 或无限制 `connect-src` 解决开发问题。

开发服务、生产 WebView、Updater、OAuth/SSO 和用户可配置远端应分开评估。临时开发 host 不能自动进入生产 CSP。修改后验证受允许资源可用，也验证未允许域被阻止。

打开 URL 前显示/记录规范化目标，限制 scheme，避免 `file:`、自定义 scheme 或认证信息注入。外部浏览器打开与 WebView 内嵌的风险不同，需分别决策。

## 5. 文件、远程与数据库

- 文件权限使用最窄目录、操作和扩展名；导入不等于允许覆盖原文件。
- SSH/服务器操作指定连接、命令和目标路径；远程写入、重启、部署、删除须明确授权。
- 数据库 DDL、批量更新和删除先查询当前 schema/数据格式、影响行数与事务/回滚路径。
- Git push/tag/release 等外部写入使用专用工作流并验证远端结果。
- 网络调用设置连接/总超时、响应大小限制和失败关闭；不能因请求失败改走不安全匿名通道。

## 6. IPC 与前端边界

- Command 只暴露完成用例所需的最小能力，不暴露通用 Shell、任意 SQL 或任意文件接口。
- Command 层做身份/窗口/参数校验，Service 层执行授权后的业务，Database/系统层保持参数化。
- 返回值移除内部路径、连接串、堆栈、秘密和不必要的个人数据。
- 高权限能力需要审批令牌/一次性上下文时，校验用途、目标、过期和重放。
- 多窗口对低信任窗口使用独立 Capability；具体 JSON 交给 `tauri-capabilities`。

## 7. 日志和审计

审计记录主体、动作、目标引用、结果、时间和关联 ID，不记录秘密正文。对失败、拒绝、远程写入和权限变化提高审计级别。

日志必须限制载荷；HTTP body、数据库记录、环境变量、请求头和命令输出默认不完整记录。错误展示给用户时使用安全摘要，内部诊断使用受控日志。

## 8. 验证清单

- 正常输入与授权路径成功；
- 未授权主体、窗口或目标被拒绝；
- 空值、超长、特殊字符、路径逃逸、恶意 URL 和重复请求被拒绝；
- 日志、错误、UI、数据库和产物中搜索不到秘密；
- 网络/远端/数据库失败不会产生部分未审计副作用；
- Capability/CSP 允许与拒绝路径在真实 Tauri 运行时验证；
- 相关测试、构建和 `git diff --check` 通过。
