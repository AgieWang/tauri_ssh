
# 与 Codex CLI 协同

## 激活边界

本技能是 `explicit-only` 外部协作能力。只有用户明确指定 Codex CLI、外部 Codex 或本技能名时才激活。

以下情况不触发：

- 普通代码实现、算法分析、Bug 排查或代码审查。
- 仅出现“Codex”作为当前运行环境的名称。
- 用户需要当前代理直接完成任务，没有提出外部委托或多模型比较。

普通任务直接使用当前代理及对应领域 Skill；不得为了“多一个意见”自行调用外部模型。

## 强制安全规则

1. 默认只读：桥接调用必须使用 `--sandbox read-only`。
2. 禁止使用 `--yolo`、`danger-full-access` 或让外部模型直接修改工作区，除非用户明确授权对应风险；即使授权，也必须遵守当前任务权限和仓库并发规则。
3. 不把 API Key、Token、密码、私钥、Cookie、连接串或凭据文件内容写入 Prompt、日志或回复；只检查配置是否存在。
4. `--cd` 必须解析为当前任务明确授权的工作区；跨仓库目录需要用户已置于任务范围内。
5. 外部输出只作为候选证据。不得直接应用补丁；先检查路径、上下文、业务契约、安全影响和与当前未提交改动的冲突。
6. 不允许外部建议替代真实代码、配置、DDL、测试、运行时或浏览器证据。
7. 保存 `SESSION_ID` 仅用于本次明确协作链路，不在文档或代码中持久化敏感会话信息。

## 执行流程

1. 确认用户明确要求外部 Codex 协作，并确定目标、输入范围和期望输出。
2. 先检查桥接脚本和 Codex CLI 是否可用；缺失时报告，不自动安装或修改凭据。
3. 默认发起只读调用。优先要求结构化分析、带文件定位的审查意见或 Unified Diff 候选。
4. 获取结果后逐项核对当前仓库事实；忽略越权、越界或与项目架构冲突的内容。
5. 如需落地代码，由当前代理重新实现或审慎应用经检查的最小补丁，并执行正常格式化、测试和审查。
6. 向用户区分“外部模型建议”和“本地已验证结论”。

## 完成条件

- 外部调用由用户明确要求，且工作区和输入范围明确。
- 调用保持只读，未泄露凭据或扩大权限。
- 外部输出已经本地代码和契约复核，没有被当作最终事实直接接受。
- 任何落地改动都通过其自身领域要求的格式化、测试、构建和审查。
