# /kickoff - 从一句话想法到自主循环开发（前门编排器）

在框架里一句话起一个新项目：**联网调研出需求 → 命名 + Logo → 工作站出原型 → 孵化新项目 → 起飞自主循环**。
每个产出都有人工门，你点头才往下——**前段你把关「做什么」，后段交给 `/dev-loop` 自主做「怎么做」**。

## 用法

```
/kickoff <一句话项目想法>
```
例：`/kickoff 做一个本地离线密码管理器，主打加密 + 生物解锁`

## 总原则

- **前 4 段交互、有人工门**，AI 不闷头冲；最后一段才进自主循环。
- **全程复用现成件**，不重复造：原型走【工作站 ui-studio】、Logo 走【工作站 logo-studio】、孵化走 `project-init` 技能、循环走 `dev-loop` 命令。
- 产出物（需求 / 品牌 / 原型）**先落在本框架**的 `docs/requirements/`、`docs/brand/`、`prototype/`，由 `project-init` 负责剪切进新项目。
- **反捏造**：调研结论标来源；需求里不确定的字段标「待确认」，不瞎填。

---

## 阶段一　需求孵化（联网 + 头脑风暴）→ 🚦人工门

1. **联网调研**：用 `WebSearch` 查同类产品 / 方案 / 技术选型 / 合规与风险；必要时调【工作站】`/research`（ai-workstation MCP：route → research-studio）做更系统的竞品对标。
2. **头脑风暴**：把「一句话想法」扩成结构化需求——目标、核心场景、功能范围与**边界（明确不做什么）**、优先级矩阵、路线图（MVP→V1→V2）。
3. **产出 PRD 草稿**写到 `docs/requirements/PRD-<名称>-v1.0.md`（UTF-8 无 BOM，用 Write）。
4. 🚦**人工门**：把「调研要点 + 完善建议 + PRD 摘要」给用户，**停下等确认 / 修改**。通过才进阶段二。

## 阶段二　命名 + Logo（必须走工作站）→ 🚦人工门

1. **命名**：从 PRD 提炼命名候选，每组给：产品名（英文窗口标题）、缩写（2-3 字母）、应用标识符（反向域名 `com.x.y`，全小写）、包名（snake_case，≤20 字符）。给 2-3 组候选 + 推荐一组。
2. **Logo**：调【AI 工作站】按产品名 + 定位设计 Logo——ai-workstation MCP → `route`（query=给 <产品名> 设计 logo）→ `get_skill`(ai-logo-studio) → 按其指导执行（优先 HTML/SVG，不优先 AI 生图）。导出主图 **`docs/brand/logo-1024.png`**（1024×1024，方形）+ 矢量 `docs/brand/logo.svg`。
   - 🔴 **禁止模型自己瞎画 logo**；一律走工作站 logo-studio。
3. 🚦**人工门**：把命名候选 + Logo 给用户看（可 `os.startfile` 打开），**停下等确认 / 修改**。
   - 确认的**命名留给阶段四 project-init 复用**（产品名 / 缩写 / 标识符 / 包名），不重复问。
   - 确认的 **Logo（`docs/brand/logo-1024.png`）会被 project-init 自动设为应用图标**。

## 阶段三　原型生成（必须走工作站）→ 🚦人工门

1. 按确认的 PRD（**带上已定的产品名 + Logo**，让侧栏标题 / 品牌位用真名真图），**调【AI 工作站】生成原型**：ai-workstation MCP → `route`（query=按需求做 UI 原型）→ `get_skill`(ai-ui-studio) → 按其指导执行，产出 `prototype/*.html`（带「组件映射表」注释 + 设计令牌 CSS 变量 `var(--xxx)`）。
   - 🔴 **禁止模型自己手搓 HTML 充当原型**；原型一律由工作站 ui-studio 出（保证可被 dev-loop 的原型保真闭环逐元素对照）。
2. 🚦**人工门**：把原型给用户看，**停下等确认 / 修改**。通过才进阶段四。

## 阶段四　孵化新项目（复用 project-init，不重写）

- **执行 `project-init` 技能**（框架自带），并**把阶段二已确认的 产品名 / 缩写 / 标识符 / 包名 直接喂给它，让它跳过重复询问**。
- 它会 `git archive` 出新目录 → 把 `docs/requirements/` + `prototype/` + **`docs/brand/`（Logo）** 剪切进新项目 → 替换标识符 / 包名 / 端口 → **用 `docs/brand/logo-1024.png` 自动生成应用图标**（`pnpm tauri icon`）→ 建私有仓库 → 写 subproject 治理文件。
- 按 `project-init` 的交互流程走，**不在本命令里重复它的逻辑**。

## 阶段五　起飞（交给 dev-loop）

- 由 `project-init` 的 Step 5.2 输出 `/loop /dev-loop` 起飞指令。
- 提示用户：**到新项目里新开 Claude Code，粘 `/loop /dev-loop`** 即自主连续开发——第 0 轮按需求+原型自拆任务台账，之后每轮一个最小单元、UI 任务走原型保真截图闭环，直到台账做完才停。

---

## 约束

- 本命令在【框架】运行，**可用 ai-workstation MCP**（区别于工作站源码仓库——那里禁用 MCP）。
- **每个人工门必须真的停下等用户**，不许自己点头连跑到底（前段的把关权在用户）。
- 产出文件 UTF-8 无 BOM；不按名杀宿主进程（按端口 / PID 精准）；本地提交不推远端（除非用户明确要求）。
- 中途任一阶段用户喊停 / 要改 → 就地改，改完重新过该门，不跳门。

## 与相邻能力的边界

| 能力 | 角色 |
|------|------|
| **/kickoff**（本命令） | 前门编排：研究→需求门→命名+Logo门→原型门→孵化→起飞，一条龙带人工把关 |
| 工作站 `/logo`（MCP） | 阶段二的 Logo 设计器（产出 `docs/brand/logo-1024.png`，兼作 app 图标源） |
| 工作站 `/ui`（MCP） | 阶段三的原型生成器 |
| `project-init` 技能 | 阶段四的孵化引擎（scaffold + 剪切资产 + 命名替换 + 图标 + 配置），已成熟，复用 |
| `dev-loop` 命令 | 阶段五之后的自主循环执行体（每轮一最小提交 + 原型保真闭环） |
