# VitePress 站点初始化

仅在用户明确要求初始化 VitePress 站点，且入口保护规则满足时读取。

## 目标位置

| 模式 | 默认路径 | 适用情况 |
|---|---|---|
| `sibling` | `../{project-slug}-docs` | 独立发布和依赖隔离，默认推荐 |
| `internal` | `./website/` | 用户明确希望站点保存在主仓库 |
| `custom` | 用户指定 | 目标已明确且位于授权范围 |

不得使用 `./update-docs/`。写入同级或自定义目录前，先解析绝对目标、检查是否已有文件，并向用户展示将创建或覆盖的范围。

## 初始化输入

优先从 `package.json` 和 `src-tauri/tauri.conf.json` 读取可验证值，缺失或冲突的值再请用户确认。

| 占位符 | 来源 | 默认/限制 |
|---|---|---|
| `{{PROJECT_NAME}}` | `productName` 或包名 | 冲突时确认 |
| `{{PROJECT_SLUG}}` | package name | 转为 kebab-case |
| `{{PROJECT_DESC}}` | package description | 不虚构业务能力 |
| `{{PROJECT_TAGLINE}}` | 已确认的产品定位 | 不用技术栈冒充产品价值 |
| `{{SITE_URL}}` | 用户提供 | 未知时保留明确占位，不伪造正式域名 |
| `{{THEME_COLOR}}` | 现有设计令牌或用户输入 | 没有依据时使用模板默认值 |
| `{{KEYWORDS}}` | 已确认产品和技术关键词 | 不包含内部项目代号或敏感词 |
| `{{DOCS_PROJECT_NAME}}` | `{slug}-docs` | 与目标目录一致 |
| `{{LOGO_LETTER}}` | 产品名/slug | 只作为占位视觉资源 |
| `{{INITIAL_COMMIT}}` | 主项目当前 HEAD | Git 不可用时明确标注 |
| `{{INITIAL_TIME}}` | 当前 ISO 8601 时间 | 记录真实生成时间 |

## 初始化步骤

1. 读取主项目 L1 Git 状态和目标目录现状，保护其他会话改动。
2. 确认目标模式、产品名、描述、主题色和站点 URL。
3. 定位实际存在的 VitePress 模板；模板缺失时停止，不凭记忆生成另一套架构。
4. 复制模板文件，保持 UTF-8 无 BOM；隐藏文件必须显式列出和检查。
5. 只替换 `.md`、`.ts`、`.css`、`.svg`、`.json` 等已知文本文件中的占位符。
6. 从当前代码生成首版章节；每个能力区分静态代码证据与运行时验证。
7. 在主项目根写入 `.docs-meta.json`，不是写到站点目录。
8. 在站点目录安装依赖并执行构建；不得修改主项目根依赖脚本。
9. 使用内置浏览器或 Control Chrome 验收首页、导航、关键章节、移动视口和控制台。

## Git 边界

- 不自动推送。
- 不执行 `git add -A` 或 `git add .`；仅逐个暂存本次生成文件。
- 初始化新 sibling 仓库和首次提交只有在用户请求包含该动作时才执行。
- 提交前列出暂存文件并排除当前任务之外的内容。
- 不 stash、reset、clean 或丢弃已有目标目录内容。

## 初始化验收

- 目标路径与 `.docs-meta.json.docsPath` 一致。
- 模板占位符无遗漏，正式站点中不存在 `example.com` 等误导性值。
- 首页、导航、搜索/链接（如配置）和至少一个内容章节可访问。
- 主项目根没有新增 VitePress 依赖或站点运行脚本。
- 用户已有文件、资源和 Git 工作没有被覆盖。
