# 经验沉淀执行与存储

仅在用户显式要求沉淀/写入经验时读取。

## 仓库模式

优先读取项目现有经验配置（如 `.codex/exp.config.json` 或项目约定），不能仅凭某个目录存在就自动写配置。

| 模式     | 项目专属资产                                    | 框架通用候选                                  |
| -------- | ----------------------------------------------- | --------------------------------------------- |
| 框架仓库 | 写规范源，镜像由同步工具生成                    | 可写规范源，但仍需逐项确认                    |
| 子项目   | 写 `.codex/PROJECT.md`、项目 Skill 或项目经验区 | 写入 `feedback-to-framework.md`，不直接改框架 |

不确定模式时先只读展示检测依据并请求确认；未经确认不创建模式配置和目录。

## 只读收集

按用户选择的范围执行最小扫描：

```bash
git log --since='7 days ago' --pretty='%h %s %an' --no-merges
git status --short
git diff --stat
rg --files docs/tasks/active docs/architecture
```

再读取最近 1～3 个与主题相关的摘要用于去重。不要默认全量扫描全部历史经验或全部源代码。

会话信号包括：用户明确纠正、相同错误反复出现、真实测试/运行时结果推翻既有规则，以及有依据的架构决策。模型自身重复输出不等于业务经验。

## 确认表

```markdown
| #   | 候选 | 类型 | 原始证据 | Why | 置信度 | 归属 | 建议目标 |
| --- | ---- | ---- | -------- | --- | ------ | ---- | -------- |
```

每条候选的写入预览必须包含完整目标路径和将修改的章节。用户可选择写入、编辑后写入、跳过或更换去向。

## 分发规则

### Skill/命令

- 加载 `add-skill` 并确认 Manifest 中的 source、platforms、activation 和 upstream 属性。
- 只改规范源；不得手工复制到镜像目录。
- 新工作流默认 explicit-only，必须有不应触发示例和验证规则。

### 项目规则

- 框架规则与项目规则分开；子项目不得改框架只读副本。
- 只追加不重复的最小规则，并提供 Why 和来源。

### Memory

- 用户必须明确说要更新/写入 Memory，并确认内容范围。
- Codex 环境按平台要求创建 Memory 更新扩展记录，不直接编辑 `/Users/.../.codex/memories/MEMORY.md`、summary 或 rollout 历史。
- 写入内容不包含凭据/PII；漂移事实带日期、来源和复核提示。

### 经验文档

- 只有用户明确要求生成文档时创建，且遵守仓库文档目录规则。
- 内容包含问题、环境、证据、决策、操作、验证、回滚和失效条件。

### 反哺队列

- 子项目的框架通用候选进入项目约定的 `feedback-to-framework.md`。
- 反哺队列不是框架已采纳规则；后续需在框架仓库重新验证和确认。

## 落盘验证

1. 检查目标仍是当前规范源，且没有其他会话的新改动冲突。
2. 使用最小补丁写入，不覆盖人工段和无关修改。
3. 检查 UTF-8 无 BOM、乱码、相对链接、重复内容和敏感信息。
4. Skill 变更运行路由/格式/镜像 check；文档运行适用的链接/构建检查。
5. 运行 `git diff --check`，报告实际写入和未执行动作。

默认不 commit、不 push、不发布到外部系统。
