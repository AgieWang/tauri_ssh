# 任务模板与状态迁移

## 目录

- 任务文档模板
- 创建与命名
- 更新片段
- 恢复摘要
- 归档规则

## 任务文档模板

```markdown
# 任务：{任务标题}

**状态**: 🟢 进行中 | 🟡 已暂停 | 🔵 已完成
**创建时间**: {YYYY-MM-DD HH:mm:ss}
**更新时间**: {YYYY-MM-DD HH:mm:ss}
**Git 分支**: {branch-or-unknown}
**相关提交**: {sha-or-none}

## 需求与完成条件

- 目标：{用户原始目标}
- 范围：{包含与不包含}
- 约束：{安全/兼容/工具/验收}
- 完成条件：{可验证结果}

## 方案与关键决策

### {决策标题}

- 候选：{方案 A / B}
- 选择：{当前选择}
- 依据：{代码、文档、数据库或运行时证据}
- 权衡：{代价与备选}

## 实现步骤

- [ ] 1. {具体动作}
  - 文件：`path`
  - 依赖：{前置}
  - 预期：{结果}
  - 验证：{命令或运行时行为}

## 问题与风险

### 问题 1：{标题}

- 现象：{可观察事实}
- 证据：{日志/路径/查询}
- 根因：{已确认或待确认}
- 处理：{动作}
- 状态：待定位 | 处理中 | 已解决

## 当前进度

- 已完成：{done}/{total}（{percent}%）
- 正在进行：{步骤}
- 最后完成：{事实}
- 下一步：{具体动作与验证}
- 阻塞：{无或说明}
- 待决策：{无或列表}

## 相关文件

- `path`：{用途}

## 变更记录

### {YYYY-MM-DD HH:mm:ss}

- 类型：创建 | 进度 | 决策 | 问题 | 验证 | 归档
- 内容：{事实}
- 影响：{范围}
```

按任务实际层次填充，不要为纯前端任务硬塞 Database/Service/Command，也不要为纯后端任务生成页面步骤。

## 创建与命名

- 目录：`docs/tasks/active/`、`docs/tasks/archive/YYYY-MM/`。
- 文件：`task-YYYYMMDD-HHMMSS-<short-kebab-or-chinese-slug>.md`。
- 时区：项目配置时区；本项目默认 Asia/Shanghai。
- slug 去掉路径分隔、控制字符和敏感内容，避免重名。
- 获取 Git 分支失败时写“未知”，不编造 master/main。

## 更新片段

完成步骤时：

```markdown
- [x] 2. 实现 Service
  - 完成时间：2026-08-01 14:30:00
  - 实际结果：新增 `ExampleService::run`
  - 验证：`cargo test example_service` 通过
```

决策变化时保留历史：

```markdown
### 存储方案

- 原选择：方案 A（2026-07-31）
- 当前选择：方案 B（2026-08-01）
- 变化原因：真实迁移测试发现 A 不支持旧库升级
- 证据：`migration_from_v33` 测试和目标库 schema
```

问题未定位时写“根因待确认”，不得把猜测写成结论。

## 恢复摘要

```text
任务：{标题}（{状态}，{done}/{total}）
目标：{一句话}
当前证据：{分支、diff、最近验证}
关键决策：{选择及依据}
已知问题：{状态}
下一步：{动作、文件、验证}
任务文件：{绝对或仓库相对路径}
```

恢复时用当前仓库验证文件、分支和测试结果；历史文档可能过期。

## 归档规则

- 用户明确要求且完成条件满足才归档。
- 归档前补齐最终验证、相关提交、未完成例外和时间。
- 精确移动一个任务文件，不使用 glob 批量移动。
- 暂停任务留在 active 或按项目约定处理，不能标为完成。
- 归档后保留原内容，不删除历史决策和已解决问题。
