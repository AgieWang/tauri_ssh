# 发布门禁与回滚

正式发布前逐项核对。任何必需项失败都停止外部写入，不以“稍后补”绕过。

## 1. 授权与范围

- 用户明确要求执行发布，而不是仅做方案、检查、打包或版本准备。
- 版本号、目标分支、目标 remote、平台矩阵、草稿/正式状态和更新说明明确。
- push、tag、创建 Release、上传产物、更新远端 manifest 等动作分别在授权范围内。

## 2. 工作区与 Git

- 记录 `git status -s`、当前分支、上游和远端 URL；远端 URL 输出不得含凭据。
- 对照本会话文件清单逐个暂存；移除暂存区中的越界文件。
- 禁止 stash、reset hard、clean、全量 add 和丢弃其他会话改动。
- 确认目标 Tag 不存在或已按用户指示处理；禁止静默覆盖远端 Tag。

## 3. 版本与变更

- 核对项目实际版本源；当前项目涉及的 `package.json`、`src-tauri/Cargo.toml`、`tauri.conf.json` 和锁文件必须一致。
- 更新说明与真实 diff 一致；敏感配置、临时文件、调试开关和本地路径未进入提交。
- 运行适用格式化、静态检查、测试、构建和 `git diff --check`。

## 4. 签名与凭据

- 私钥/密码只通过 CI Secrets、Safe Credentials 或受控环境注入。
- 日志、命令回显、错误、manifest、提交和发布说明不含秘密。
- 公钥、签名、平台、架构和对应产物一一匹配；坏签名必须失败关闭。

## 5. CI 与产物

- CI 使用的提交 SHA/Tag 与准备发布的版本一致。
- 所需平台任务全部成功；排队中、跳过或单平台成功不算全平台完成。
- CI 完成且产物预检通过前，不写 release 仓库、CDN、README 或 manifest。
- 按当前 workflow 和启用 target 动态计算精确产物集合；全桌面常见为 11 个而非 12 个，但不得硬编码总数。
- 每个 App/版本使用独立目录；按 App 前缀、版本和 target 唯一匹配产物及 `.sig`。
- 校验名称、架构、大小、hash、签名、安装/启动以及下载 URL；所有启用 target 逐一通过。
- CI/API 轮询设置总超时；状态或 JSON 解析失败即停止。

## 5.1 签名与 Manifest 一致性

- 每个启用 updater target 的 `.sig` 必须正好一份，禁止宽 glob、拼接或 `eval`。
- 签名去除换行后执行 Base64 解码和重新编码比对。
- 使用结构化 JSON 生成 manifest；生成后逐 target 对比原 `.sig`、URL、版本、平台与架构。
- 下载/公开 URL 检查必须包含失败状态、超时、HTTP 状态、大小及可用 hash，不能只检查命令退出文本。

## 6. 外部发布验证

- 修改 release 仓前先同步远端；冲突立即停止。
- 逐文件暂存，禁止全量 add；任一 push 失败停止后续发布。
- 推送后读取远端分支和 Tag，确认目标 SHA。
- 创建或更新 Release 后读取远端状态，确认草稿/正式标记和附件。
- 远端 manifest 可访问，字段、URL、签名和版本正确；对至少一个目标平台执行更新检查。

## 7. 失败与回滚

- 任何一步失败立即停止后续写入，记录已产生的远端对象和当前状态。
- 优先补救或发布新修复版本；不要重写已被客户端消费的版本/Tag/manifest。
- 删除或覆盖远端对象属于新的破坏性动作，必须重新获得明确授权。
- 向用户报告可恢复性、需要人工处理的凭据/平台动作和仍未验证的生产风险。

## 8. Android 附加门禁

- 桌面和移动 Tag/CI job/产物目录互斥；移动 Tag 不能触发桌面发布。
- 移动端各版本源一致，`versionCode` 严格递增。
- 使用稳定 release keystore；keystore 与密码不提交，且所有 CI remote 的 Secrets 配置一致。
- 每个 APK 用 `apksigner` 比对预期 release 证书指纹；debug/未知签名拒绝发布。
- 侧载 APK/AAB 不生成桌面 Updater manifest。
