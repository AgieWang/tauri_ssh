## Purpose

定义团队知识项目及其多 Git 仓库目录契约，使微服务项目能够在一个项目上下文中管理多个只读代码与文档来源，并保持清晰归属和同步状态。

## ADDED Requirements

### Requirement: 管理知识项目
系统 SHALL 允许用户创建、查询、修改、停用和软删除知识项目，并 SHALL 为项目保存稳定标识、唯一名称、描述、别名、默认版本策略和审计时间。

#### Scenario: 创建项目
- **WHEN** 用户提交合法且未被占用的项目名称
- **THEN** 系统创建项目并返回稳定项目标识，项目立即可用于关联仓库和文档

#### Scenario: 项目名称重复
- **WHEN** 用户提交与现有有效项目规范化后相同的名称
- **THEN** 系统拒绝创建并返回可定位到名称字段的冲突错误

### Requirement: 关联多个 Git 仓库
系统 SHALL 允许一个知识项目关联多个已登记 Git 工作区，并 SHALL 为每个关联保存业务别名、仓库角色、默认分支、启用状态、版本映射规则和最近同步状态。

#### Scenario: 添加多个微服务仓库
- **WHEN** 用户为同一项目选择多个不同的 Git 工作区
- **THEN** 系统分别创建仓库关联，任一仓库失败时不得留下部分成功的批量关联

#### Scenario: 仓库已经关联
- **WHEN** 用户重复关联同一项目和同一 Git 工作区
- **THEN** 系统返回已有关联或幂等更新结果，不创建重复关联

### Requirement: 在不修改仓库的前提下验证可用性
系统 MUST 只读验证仓库路径、Git 状态、当前 HEAD、分支和 Tag 可发现性，并 MUST 不执行 checkout、stash、reset、clean、pull、push、Hook 或仓库脚本。

#### Scenario: 检查存在未提交改动的仓库
- **WHEN** 已关联仓库存在未提交改动
- **THEN** 系统显示 dirty 状态并仍可读取明确选择的快照，但不得修改工作区或把工作树表述为发布版本

### Requirement: 解除关联时保留仓库历史
系统 SHALL 在解除仓库与项目的当前关联时保留已生成的历史版本、文档、引用和审计，并 SHALL 明确提示后续同步将停止。

#### Scenario: 解除已建立索引的仓库关联
- **WHEN** 用户确认解除一个已有索引记录的仓库
- **THEN** 系统停用该关联且保留历史证据，除非用户另行发起经过确认的历史数据清理

### Requirement: 提供线性项目初始化
系统 SHALL 为普通用户提供“创建项目、选择仓库、选择版本、确认同步”的线性引导，默认只显示每一步必填内容并自动填充可安全推断的默认值；仓库角色、逐仓库规则和其他低频配置 SHALL 收纳到高级设置，用户返回上一步时 MUST 保留已填写内容。

#### Scenario: 首次创建多仓库项目
- **WHEN** 没有知识库配置经验的用户首次创建项目并选择多个已登记 Git 工作区
- **THEN** 系统使用简短中文说明逐步引导，最后展示项目、仓库和版本摘要，用户无需理解内部标识或 Git 命令即可确认创建
