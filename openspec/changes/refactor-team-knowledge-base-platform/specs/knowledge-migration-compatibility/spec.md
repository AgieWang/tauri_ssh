## Purpose

定义从现有 schema v36 与知识库 API 迁入新领域模块的兼容、校验和回滚行为，确保重构不会清空历史索引、破坏引用或强迫一次性切换全部客户端。

## ADDED Requirements

### Requirement: 无损升级现有数据库
系统 SHALL 从 schema v36 通过连续前向迁移增加新结构，并 MUST 保留现有项目、版本、来源、文档、片段、向量、关系、任务和源码分析记录。

#### Scenario: 升级包含数据的 v36 数据库
- **WHEN** 应用首次打开包含有效知识数据的 v36 数据库
- **THEN** 迁移完成后记录数、稳定标识、引用关系和活动 Profile 均可核对，旧数据可由新查询读取

### Requirement: 保证迁移原子性并支持安全重启
系统 SHALL 对每个版本跃迁使用可验证事务或明确的分阶段检查点，失败时 MUST 不留下被误认为完成的半迁移状态。

#### Scenario: 数据回填期间迁移失败
- **WHEN** 新字段回填或索引构建失败
- **THEN** 系统保持旧 schema 版本或可识别的未完成状态，拒绝启动不兼容写入并提供安全重试

### Requirement: 迁移期间保持公共接口兼容
系统 SHALL 在迁移窗口保留现有知识 Command 名称、请求/响应字段和 TypeScript API 外观，内部由兼容 Facade 路由到新领域模块；无法兼容的变化 MUST 另行声明为破坏性变更。

#### Scenario: 现有客户端查询项目列表
- **WHEN** 旧前端调用仍受支持的项目列表接口
- **THEN** 系统返回与旧契约兼容的数据，同时由新目录模块提供结果

### Requirement: 重建派生数据时不删除来源事实
系统 SHALL 将全文索引、向量和图谱视为可重建派生数据；重建失败时 MUST 保留源文档版本和上一个可用索引。

#### Scenario: 新图谱投影无效
- **WHEN** 迁移后的图谱完整性校验失败
- **THEN** 系统继续使用旧关系查询或禁用图谱新入口，不删除文档与关系事实

### Requirement: 支持按功能开关发布与回滚
系统 SHALL 按项目或阶段启用新目录、文档、搜索、图谱和问答入口，并 SHALL 能在不回退数据库版本的情况下关闭新路径恢复旧入口。

#### Scenario: 新搜索路径超过错误阈值
- **WHEN** 观测门禁判定新搜索错误率或版本串用率不可接受
- **THEN** 系统关闭新搜索路由并恢复旧兼容路径，保留诊断数据供修复

### Requirement: 将 UI 兼容限制在入口与数据
系统 SHALL 保持 `/knowledge` 入口、历史数据、权限和受支持 API 可用，但 MUST 以本变更确认的新用户流程呈现知识工作台；现有 UI 的 Tabs、布局、字段排列、配置步骤、文案、状态组织和交互组件 SHALL 不作为兼容要求或新 UI 实现依据。

#### Scenario: 现有用户进入新版知识库
- **WHEN** 新知识工作台启用后用户通过原 `/knowledge` 地址进入
- **THEN** 系统打开全新的项目上下文或首次使用流程并可读取原有数据，不恢复或复制旧页面的交互结构
