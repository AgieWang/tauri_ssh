## Why

现有团队知识库已具备项目、版本、Git 来源、全文/向量检索和源码分析基础，但实现集中在超大 Rust/React 文件中，现有 UI 交互也过于复杂、凌乱，不适合作为后续设计基础；继续叠加功能会放大契约漂移、使用门槛、迁移风险和验收盲区。现在需要把知识库重构为以“项目—仓库—版本—文档—证据”为主线的可扩展平台，同时重新设计面向普通用户的操作流程，并补齐多格式文档、人工版本、图谱和准确问答闭环。

## What Changes

- 将现有知识库按项目目录、来源接入、文档处理、检索、向量、图谱、源码分析、问答、任务和治理拆分为独立领域模块，保持 React → API → Command → Service → Database 的单向依赖。
- 用户可创建项目，并为一个项目关联多个已登记 Git 仓库；每个仓库独立保存默认分支、版本规则、授权范围和同步状态。
- 建立统一文档接入流水线，读取 Markdown、纯文本、Office、图片和 HTML 原型等文档，保留原文件、解析文本、结构块、附件和来源证据。
- 提供知识文档的手工新增、编辑、查询、软删除、恢复和自定义文件上传；所有写操作形成不可变文档版本。
- 提供标题搜索与全文搜索，并与项目、仓库、版本、文档类型、来源和权限过滤组合；语义检索作为可选增强而非标题/全文搜索的替代。
- 允许用户选择 Git 分支或 Tag 建立项目版本快照，在不 checkout、不修改工作区的前提下读取历史内容并记录确定 Commit SHA。
- 允许 AI 对指定仓库快照做只读代码分析，生成带文件/符号/Commit 引用的草稿分析文档；用户查看、编辑并确认后才写入正式知识库。
- 自定义文档支持草稿、提交、版本比较、回退式新版本和项目版本绑定，不覆写历史正文。
- 从文档、代码符号和已确认关系生成项目知识图谱，提供按项目/版本过滤、邻接展开、证据查看和关系确认。
- 支持本地与远程 Embedding，向量及 Profile 元数据始终存储在本地 SQLite；远程处理默认关闭并需要来源级授权。
- 提供证据约束的 AI 问答：先做项目/版本硬过滤，再融合标题、全文、向量和关系召回；回答必须引用来源，证据不足或冲突时明确拒答/提示。
- 长耗时解析、同步、源码分析、向量化和图谱构建统一进入持久化任务系统，支持进度、取消、重试、恢复和幂等执行。
- 面向普通用户的项目初始化、仓库关联、版本选择、文档上传、搜索、向量配置和问答采用线性引导与渐进式展示；默认只呈现必要字段和推荐值，技术参数统一收纳到高级设置，界面使用简短中文业务文案。
- **BREAKING（用户界面）**：新知识工作台从已确认的用户任务重新设计，不继承现有 UI 的 Tabs、布局、字段排列、配置步骤、文案、状态组织或交互测试快照；现有页面仅用于盘点功能和核对接口/数据，不作为新 UI 参考。
- 对现有 schema v36 数据、Command/API 和已建立索引提供分阶段迁移与兼容层，禁止通过删除旧表或清空索引完成重构。
- 增加检索质量、引用准确率、版本串用率、任务失败率、解析覆盖率和性能基线，作为阶段开放和回滚门禁。
- 所有强制验证与验收必须能在当前 macOS 本机完成；远程模型、视觉和向量接口使用本机回环测试服务或可控测试 Provider 验证，连接真实外部服务不作为本变更完成门禁。

## Capabilities

### New Capabilities

- `project-repository-catalog`: 创建知识项目、关联多个 Git 仓库，并管理仓库授权、同步与项目归属。
- `document-ingestion-pipeline`: 安全读取 Markdown、Office、图片、HTML 原型及其他受支持格式，形成统一解析产物和来源证据。
- `managed-document-lifecycle`: 手工新增、编辑、查询、软删除、恢复和上传知识文档，并处理冲突与审计。
- `knowledge-search`: 提供标题搜索、全文搜索、筛选、排序、分页和可解释命中信息。
- `ai-code-analysis`: 对 Git 快照进行只读 AI/静态分析，生成可审阅、可编辑、可确认的项目分析文档。
- `project-version-governance`: 以 Git 分支或 Tag 解析不可变项目版本，隔离不同版本的文档、代码和问答证据。
- `custom-document-versioning`: 对人工与上传文档提供草稿、提交、版本比较、项目版本绑定和历史恢复。
- `knowledge-graph`: 从文档、代码实体和已确认关系生成、查询和可视化项目知识图谱。
- `embedding-index-management`: 管理本地/远程 Embedding Profile、本地向量存储、增量构建、蓝绿切换和回滚。
- `evidence-grounded-qa`: 通过项目/版本硬过滤和混合召回生成带引用、可拒答的项目知识问答。
- `knowledge-job-orchestration`: 统一编排同步、解析、分析、向量化和图谱任务，提供持久化进度、取消、重试和恢复。
- `knowledge-security-governance`: 约束本地路径、凭据、远程处理、敏感内容、审计和只读 Git/MCP 边界。
- `knowledge-migration-compatibility`: 将现有知识库数据与 API 平滑迁入新领域模型，保持可回滚和旧客户端兼容窗口。
- `knowledge-observability-evaluation`: 记录数据质量、检索/问答准确性、版本隔离、任务健康和性能指标，控制阶段开放。

### Modified Capabilities

无。`openspec/specs/` 尚无已发布主规格；本变更将新能力作为完整契约提出，并在实施前与未归档的 `add-team-knowledge-base-rag` 逐项对齐，避免重复或冲突实现。

## Impact

- Rust：拆分 `commands/knowledge.rs`、`services/knowledge.rs`、`database/knowledge.rs` 和 `models/knowledge.rs`，新增格式解析器、文档版本、图谱、分析草稿、任务与迁移模块。
- React/TypeScript：将 `src/pages/knowledge/index.tsx` 收敛为入口或隔离的旧版回滚壳，从新的用户流程建设项目/仓库、文档、搜索、版本、图谱、分析审核和问答页面；复用类型化 API 与基础设计令牌，但不复用旧页面的交互结构。
- SQLite：从 schema v36 追加不可逆向下兼容的前向迁移，复用已有项目、版本、来源、文档、片段、向量、关系和任务数据，并增加上传资产、草稿/提交、图谱投影及评测记录。
- 依赖：需要评估 Office 解包/解析、HTML 清洗、图片元数据/可选 OCR、图谱可视化和文件对话框依赖；正式引入前必须完成当前目标平台 macOS 的构建、安全和包体 Spike。
- 安全：Git、文件、AI Provider 和远程 Embedding 继续使用现有 Git 工作区、Safe Credentials、来源授权、敏感检测和审计边界；分析不得执行仓库代码。
- 验收：使用本机仓库、文件夹具、SQLite、Tauri IPC、浏览器、本地模型及回环测试 Provider 完成闭环，不依赖外部服务器、生产环境或真实远程 Provider。
- 兼容：优先保留数据库、现有 Command 与 TypeScript API 外观，通过领域 Facade 渐进迁移；兼容范围不包含旧 UI 交互，`/knowledge` 只保证入口可达并进入新工作台。
