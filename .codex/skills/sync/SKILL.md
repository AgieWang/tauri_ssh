# /sync

`/sync` 是项目管理文档的显式全量同步工作流。业务数据同步、数据库同步、接口同步、框架代码同步和普通“保持一致”不触发。

扫描口径和更新格式按需读取 [`references/project-doc-sync.md`](references/project-doc-sync.md)。

## 目标边界

默认只处理仓库已经存在且用户确认的项目管理文档，例如：

- `docs/项目状态.md`
- `docs/待办清单.md`
- `docs/需求文档.md`

实际文件名以仓库为准。缺失文档只报告，不因 `/sync` 自动创建；创建文档需要用户明确要求。

## 执行流程

1. 读取仓库约束、Git 状态、目标文档和文档内的人工维护边界。
2. 用 `rg --files`/`rg` 扫描代码结构、TODO/FIXME、活跃任务、项目状态文档与最近提交，避免全量加载源码。
3. 建立“文档陈述 → 当前代码/任务证据”的差异表，区分确定冲突、疑似冲突和无法验证。
4. 展示每个目标文件将修改、保留和待人工确认的内容，等待用户确认后再写。
5. 写入前为本次目标文件建立可恢复副本或补丁；只修改可由证据确定的区域。
6. 验证 UTF-8 无 BOM、Markdown/链接、人工内容保留和 `git diff --check`，输出同步报告。

## 准确性与回滚

- 代码、任务和真实运行结果发生冲突时不自动选择一方；报告证据并请求确认。
- 模糊匹配不能自动把待办标为完成，需求状态也不能仅凭 commit message 更新。
- 保留人工段落、历史说明和未识别字段；禁止整文件模板覆盖。
- 只回退本次同步改动，禁止使用 stash、reset、checkout 文件或 clean。
- 不提交、不 push；若用户明确要求 Git 操作，交给 `git-workflow` 并逐文件暂存。

## 不应触发

- “同步 ADB 数据”——数据库/业务同步任务。
- “同步框架最新代码”——框架/Git 工作流。
- “更新一篇 VitePress 文档”——使用 `docs-management` 或显式 `/update-docs`。
