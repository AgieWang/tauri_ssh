# 持久化任务跟踪

## 目标

用 `docs/tasks/active/` 与 `docs/tasks/archive/` 保存用户明确要求持久化的需求、决策、进度和问题，使后续会话能从仓库证据恢复上下文。

## 激活边界

启用：

- 用户明确说“创建/记录/跟踪任务”。
- 用户要求“恢复/继续/查看/归档任务”。
- 用户明确说明这是长期、多会话工作，并同意落盘跟踪。

不启用：

- 普通多步骤开发、单次会话 TODO 或执行计划。
- 只讨论方案、做技术调研、排查问题但未要求持久化。
- 项目整体进度报告、Git 提交说明或外部 Issue 管理。

未命中时使用运行时计划，不创建 `docs/tasks/*.md`。

## 强制边界

- 项目规则禁止主动生成文档；只有用户明确要求持久化任务时才可写入。
- 创建、更新、归档前读取当前任务文件和 `git status -s`，避让其他会话改动。
- 不自动归档、删除或覆盖任务；多个候选无法确定时列出并让用户选择。
- 记录事实与证据，不把未运行检查写成通过，不把计划写成已完成。
- 任务文档不得保存密码、Token、私钥、完整凭据或未脱敏生产数据。
- 时间使用项目时区，进度从顶层可执行复选框一致计算。
- 归档是文件移动，必须保留历史；禁止使用清理命令删除旧任务。

## 工作流

### 1. 发现任务状态

先判断目录是否存在；不存在表示当前没有持久化任务，不能让发现命令报错：

```bash
if [ -d docs/tasks/active ]; then
  find docs/tasks/active -maxdepth 1 -type f -name 'task-*.md' -print
fi
if [ -d docs/tasks/archive ]; then
  find docs/tasks/archive -type f -name 'task-*.md' -print
fi
```

读取候选文件的标题、状态、更新时间和进度。不要用“最新文件”替代用户指定关键词；无唯一候选时请求选择。

### 2. 创建任务

读取 [task-templates.md](references/task-templates.md) 的“创建模板与命名”。

1. 从用户原始请求提取目标、范围、约束、完成条件和待决策项。
2. 按真实项目分层生成步骤，省略不涉及的层；不要机械复制全栈清单。
3. 在已获得本次任务文档写入授权后，精确创建 `docs/tasks/active` 与 `docs/tasks/archive`（不存在时执行 `mkdir -p docs/tasks/active docs/tasks/archive`）。
4. 创建唯一文件名 `task-YYYYMMDD-HHMMSS-<slug>.md`。
5. 写入 `docs/tasks/active/`，状态为进行中，进度为 0 或已有事实进度。
6. 复读文件，确认字段、编码、引用和复选框完整。

首次目录说明只有用户明确要求时才创建；不要为辅助说明主动新增 README。

### 3. 更新进度或记录决策

读取目标文件后只修改对应章节：

- 完成步骤：从 `[ ]` 改为 `[x]`，写实际结果和验证证据。
- 方案变化：保留旧方案和权衡，更新最终选择及原因。
- 技术调研：记录实际版本、来源、采用结论和风险。
- 问题：记录现象、证据、根因、处理和状态；未定位时不要编造根因。
- 变更记录：追加时间、类型、内容和影响范围。

更新“更新时间”“当前状态”“下一步”“阻塞”和进度比例。避免重写用户手工内容或历史记录。

### 4. 恢复任务

读取完整任务文件，并用当前仓库只读证据复核容易漂移的内容：相关文件是否存在、Git 分支、未提交差异、最近验证结果。

恢复摘要包含：

1. 目标和明确范围。
2. 已完成与未完成步骤。
3. 关键决策及其依据。
4. 已知问题、阻塞和风险。
5. 下一步具体动作与验证出口。

任务文档是历史上下文，不是当前真实状态的唯一来源。

### 5. 归档任务

仅在用户明确要求归档，且完成条件已核对后：

1. 将状态改为已完成，记录最终验证和相关提交。
2. 按 `YYYY-MM` 创建明确归档目录。
3. 将精确任务文件移动到归档目录。
4. 验证 active 中不再存在、archive 中内容完整。

未完成但暂不推进的任务标记暂停，不冒充完成归档。

## 引用索引

- [task-templates.md](references/task-templates.md)：任务文档、创建、恢复、更新、问题和归档模板。

## 完成条件

- 用户明确授权本次任务文档写入或归档。
- 精确目标文件已读取，未覆盖其他会话内容。
- 状态、进度、决策、问题、下一步和时间相互一致。
- 所有“已完成/已通过”均有代码、命令或运行时证据。
- UTF-8 无 BOM，Markdown 结构与引用有效，`git diff --check` 通过。
