# 数据库真实核验参考

仅在实现依赖 DDL、数据格式、迁移结果、查询计划或远程数据源时读取。

## 事实来源顺序

1. 当前任务字段说明和明确契约。
2. 项目 `src-tauri/src/database/schema.rs`、DAO SQL、模型及迁移测试。
3. 实际 SQLite 文件的只读 `PRAGMA` 与样本查询。
4. 涉及外部数据库时，读取 `script/`、Nacos 等配置定位真实数据源，再通过 Tauri SSH MCP 只读查询。
5. 文档和示例只能辅助，不能覆盖真实契约。

不得在输出中暴露连接串、用户名、密码、Token 或安全凭据。

## 本地 SQLite 核验

在确认数据库文件路径和副本安全后，优先只读检查：

```sql
PRAGMA user_version;
PRAGMA table_info(target_table);
PRAGMA index_list(target_table);
PRAGMA foreign_key_list(target_table);
SELECT sql FROM sqlite_master
WHERE type IN ('table', 'index') AND tbl_name = 'target_table';
```

不要在未知或正在使用的真实库上直接试跑破坏性迁移。迁移验证使用临时副本/测试库，保留原库。

## 数据格式抽样

针对实现实际依赖的字段做最小只读抽样：

- `NULL`、空字符串、缺省值分别出现的比例。
- 时间字符串的格式、时区和异常值。
- JSON 文本的版本、缺失字段和损坏数据。
- 枚举/状态的真实值域，而不是只看样例。
- 自然键重复、前后空白、大小写和 Unicode 情况。
- ID 是否可能超过前端安全整数。

查询必须带明确表、列、条件和 `LIMIT`；大表聚合前先估计成本。

## 查询与索引验证

- 用真实 SQL、真实谓词顺序和代表性参数执行 `EXPLAIN QUERY PLAN`。
- 核对是否使用目标索引、是否发生全表扫描、临时排序或不可选择条件。
- 比较冷/热执行和代表性数据量；测试通过不代表性能达标。
- 新索引同时评估写入成本、数据库体积和重复索引。

## 迁移验证

至少准备：空库、上一版本库、包含边界数据的旧库。验证迁移前后：

- `user_version` 仅在成功后前进。
- 行数、关键聚合、唯一键和关联关系保持。
- 新列默认值与 `NULL` 行为正确。
- 失败不会丢表/丢列/丢数据，或有经过验证的恢复步骤。
- 应用能以新 Schema 完成真实读写路径。

## 交付证据

记录执行的测试、目标版本、只读 DDL/格式核验结论、查询计划和未验证项。构建通过只能作为中间证据，不能代替真实数据库行为验证。
