# autonomous-dev

这是显式连续开发工作流。普通“开发功能”“批量修复”“继续”“完成它”不自动触发；一次性的编码任务使用对应领域 Skill。

## 每轮闭环

1. 回读需求、原型、任务台账和仓库约束，不依赖上一轮记忆。
2. 选择依赖已满足的第一个未完成最小项；没有台账时，只有用户要求记录任务才创建台账，否则使用当前运行时计划。
3. 只实现该最小项，先读相邻参考代码并保持既有分层和风格。
4. 按实际变更文件执行格式化、类型检查、编译和聚焦测试；涉及 UI 时必须用 Codex 内置浏览器或 Chrome 做运行时验收。
5. 检查 `git diff --check`，记录实际结果、失败项和剩余风险。
6. 只有用户明确要求提交时，才逐文件暂存并创建最小提交；禁止 `git add -A` 或 `git add .`。
7. 汇报本轮完成项、验证证据和下一项。若平台允许继续且未触发停止条件，再进入下一轮。

## 验证与准确性不变量

- 验证由实际改动决定，不能因为 Skill 路由精简而省略：Rust 运行 `cargo fmt --check`、聚焦 `cargo test`/`cargo check`；前端运行格式化、类型检查、聚焦测试和必要构建。
- 涉及数据库 DDL 或真实数据格式时，先读 `script/`、Nacos 配置，再通过 Tauri SSH MCP 查询；不得凭样例猜 schema。
- 涉及权限、凭据、服务器、Git 远端或发布时，加载对应安全/发布 Skill；连续开发请求不会扩大外部写入权限。
- 保留用户和其他会话的未提交改动；不得 stash、reset、clean、切分支或覆盖不在本轮范围内的文件。

## 停止与回滚

- 同一问题连续两轮无法通过验证，或连续三轮没有实质进展：停止并提供错误原文、已尝试路径和建议。
- 遇到不可逆操作、合规/架构决策、缺凭据或需要新增外部授权：停止并请求用户决定。
- 验证失败时不勾选完成、不提交；只回退本轮明确产生且可安全回退的内容，不触碰他者改动。
- 任务和验收项全部完成后停止循环，输出最终验证矩阵和仍需真实环境验收的事项。

## 不应触发

- “帮我开发一个页面”——路由到 `ui-frontend` 等领域 Skill。
- “继续修改这个函数”——属于普通续作，不启动多轮自治。
- “批量查询数据库数据”——属于业务/数据库任务，不是连续开发工作流。
