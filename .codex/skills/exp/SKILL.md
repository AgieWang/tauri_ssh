# /exp

`/exp` 是显式经验沉淀入口。普通“总结一下”“之前怎么做”“记一下当前进度”不自动触发，也不产生任何写入。

详细分类、置信度、仓库模式、存储位置和审计方法按需读取 [`../exp-sediment/SKILL.md`](../exp-sediment/SKILL.md)。

## 子命令

| 输入 | 范围 |
|---|---|
| `/exp` | 当前会话和最近 7 天提交 |
| `/exp session` | 仅当前会话 |
| `/exp commits N` | 最近 N 天提交 |
| `/exp review` | 只审计既有经验资产，写报告前仍需确认 |

## 执行步骤

1. 只读识别仓库模式、最近提交、未提交变更、活跃任务和最近沉淀摘要。
2. 过滤敏感信息、一次性事实和重复候选，最多展示 10 条。
3. 为每条候选给出原始证据、类型、置信度、建议去向、写入预览和 Why。
4. 等待用户逐项或批量确认。未确认的候选不得写入；“分析候选”不等于“授权写入”。
5. 仅写入用户确认的目标，并保留已有内容和其他会话改动。
6. 对实际修改执行 UTF-8、引用、格式和差异检查，再报告写入结果。

## 写入授权边界

- **只有用户明确要求更新 Memory 时才允许写 Memory**。调用 `/exp`、要求总结会话或确认其他类型候选，都不能推定为 Memory 写入授权。
- Codex Memory 只能通过平台允许的扩展/更新机制写入；禁止直接编辑全局 Memory 注册表或历史记录。
- 新建或修改 Skill 时加载 `add-skill` 并遵守规范源和镜像规则。
- 修改仓库规范、项目文档或任务台账前，必须展示目标文件和内容预览并取得确认。
- 禁止记录 token、密码、私钥、真实用户数据或客户敏感信息。
- 不自动提交、不 push、不向外部系统发布。

## 完成条件

- 每条已写入经验都有来源、Why、适用范围和目标文件。
- 用户未确认的候选保持只读，不创建“默认摘要”文件。
- 写入后的引用有效、文件为 UTF-8 无 BOM，且 `git diff --check` 通过。

## 不应触发

- “总结一下刚才改了什么”——直接给会话总结，不写资产。
- “以前这个 Bug 怎么处理”——按正常 Memory 检索规则查证，不启动 `/exp` 写入流程。
- “把 TODO 状态记下来”——属于任务跟踪或项目状态，不是经验沉淀。
