# 经验沉淀指南

本 Skill 是显式 `/exp` 工作流的详细规则。普通“以前”“之前”“类似问题”“总结”“记一下”不自动触发，也不授权任何写入。

按需要读取：

- 候选类型、Tauri 重点和评分：[`references/candidate-catalog.md`](references/candidate-catalog.md)
- 仓库模式、确认和落盘规则：[`references/execution-and-storage.md`](references/execution-and-storage.md)
- 审计、模板、防腐化和回滚：[`references/audit-and-templates.md`](references/audit-and-templates.md)

## 两种显式模式

### 查询已有沉淀

只有用户明确要求“查项目沉淀/历史经验”时使用：

1. 从与主题匹配的索引或摘要开始，不全量加载经验目录。
2. 返回来源、适用范围和可能过时点；易漂移事实尽量用当前源码/运行时复核。
3. 全程只读。查询请求绝不升级为“顺便整理/更新 Memory”。

### 产出经验

只有用户明确要求沉淀/审计时使用：

1. 只读收集用户指定范围内的会话、提交、任务和最近摘要。
2. 过滤敏感信息、一次性状态、无 Why 和重复候选。
3. 最多展示 10 条候选，逐条提供证据、类型、置信度、归属、目标和完整写入预览。
4. 等待用户确认；没有确认的候选不写入任何位置。
5. 分类型最小写入并验证，最后报告实际落盘与跳过项。

## 不可削弱规则

- **Memory 只能在用户明确说要更新/写入 Memory 时修改。** `/exp`、总结、审计、确认 Skill/文档候选都不构成 Memory 授权。
- Codex Memory 遵守平台的扩展更新机制；不得直接编辑全局 Memory、索引或历史记录。其他客户端的 Memory 路径也必须按该平台规则处理。
- 每条经验必须有 Why、证据、适用范围和失效条件；没有 Why 不落盘。
- 优先补强现有资产，避免重复新建 Skill、规范或文档。
- 项目专属经验不能直接写入框架规范；框架通用候选先进入反哺队列并由用户确认。
- 包含 token、password、secret、私钥、真实用户数据或客户敏感信息的候选自动跳过。
- 不自动 commit/push，不把分析、审计或用户选择“A”解释为外部写入授权。

## 准确性与验证

- 先确认目标资产当前存在、规范源和人工维护边界，再编辑。
- 修改 Skill 时加载 `add-skill`；修改项目规则时检查与 `AGENTS.md`/`.codex/PROJECT.md` 的优先级和冲突。
- 写入后检查 UTF-8 无 BOM、链接和相对引用、重复项、陈旧路径、敏感信息与 `git diff --check`。
- 回滚只能撤销本轮明确写入，不用 stash、reset、checkout 或 clean，不覆盖其他会话改动。

## 不应触发

- “之前这个 API 怎么实现的”——直接查当前代码和必要的 Memory，不启动经验资产工作流。
- “总结本次修改”——给任务总结，不写经验文件。
- “记下 TODO”——使用运行时计划或明确的任务跟踪流程。
