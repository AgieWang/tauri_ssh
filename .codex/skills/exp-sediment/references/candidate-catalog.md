# 经验候选分类与评分

仅在显式经验沉淀请求中读取。

## 六类候选

| 类型 | 识别标准 | 常见去向 | 写入前检查 |
|---|---|---|---|
| ① 新 Skill | 独立领域反复出现，现有 Skill 无法覆盖 | 项目规范源的 skills | 先查重；加载 `add-skill`；用户确认 |
| ② 现有 Skill 漏洞 | 已有 Skill 在真实任务中遗漏关键边界 | 对应 Skill/反哺队列 | 有错误证据和 Why；不扩成通用教程 |
| ③ 新禁令/规范 | 用户明确给出可复用的禁止或必须规则 | 项目规则或领域 Skill | 区分普适规则与一次性修复；检查冲突 |
| ④ 用户偏好/项目事实 | 未来任务会复用且非短期状态 | Memory | 用户必须明确授权写 Memory；标注可能漂移 |
| ⑤ 最佳实践记录 | 多步骤、跨文件、有独特权衡但不适合 Skill | 经验文档 | 用户明确要求文档；包含复现和失效条件 |
| ⑥ 高频工作流 | 同一多步骤操作反复出现，值得显式入口 | command 类 Skill | 必须 explicit-only；不要扩大自动触发池 |

优先级：② 补强已有资产 > ③/④ 明确规则或事实 > ⑤ 经验文档 > ①/⑥ 新建资产。

## 候选必须回答

- 原始证据是什么，出现在哪里？
- 为什么未来还会复用？
- 适用于哪个仓库、模块、平台和版本？
- 什么时候会失效，如何复核？
- 现有资产是否已覆盖？
- 目标位置是规范源还是生成镜像？
- 是否包含凭据、个人信息或商业敏感数据？

## 置信度

| 证据 | 分值 |
|---|---|
| 用户明确说“记住/以后/不要/必须” | +3 |
| 同类信号至少出现两次 | +2 |
| 只有一次信号 | +1 |
| Why 清楚且可复核 | +1 |
| 能映射到具体资产 | +1 |
| 有 commit、测试或运行时证据 | +1 |

- 5 分及以上：高置信，但仍需用户确认写入目标。
- 3～4 分：中置信，必须逐项确认。
- 1～2 分：低置信，默认只报告不建议写入。

置信度不能替代授权，尤其不能替代 Memory、外部仓库或全局规范写入授权。

## Tauri 高价值信号

### Rust 错误传播

- `unwrap`/`expect` 导致后端崩溃、AppError 转换、跨线程错误丢失。
- 候选应写明触发路径、用户可见后果和正确错误边界，不能简单沉淀“禁止 unwrap”。

### IPC 契约

- Command 注册遗漏、Rust/TypeScript 参数命名、serde 字段、错误结构不一致。
- 记录完整调用链和实际失败证据，字段说明优先于样例。

### Capabilities 与凭据

- Tauri 2 权限/作用域缺失、凭据越界、审计链路遗漏。
- 不得在经验里保存真实凭据；安全策略需由对应安全 Skill 复核。

### 状态、事件与并发

- `State<T>` 的 Send/Sync、Mutex 死锁、长任务阻塞、emit/listen 生命周期。
- 必须给出平台/版本与复现条件，避免把一次并发 Bug 泛化。

### 数据库与迁移

- SQLite schema/user_version、真实外部数据库格式、事务与回滚。
- 经验事实应通过当前 DDL/数据复核，不能只根据 DTO 或示例写入。

### 打包、签名与更新

- 平台差异、CI 产物、签名、update manifest 和客户端更新。
- 只记录安全的流程和指针，不记录密钥；易漂移配置标注复核方式。
