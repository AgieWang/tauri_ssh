# 创建、修改、重命名与删除

## 创建

1. 明确真实使用示例、正反向触发、相邻 Skill 边界和平台。
2. 分析重复执行所需的 references、scripts、assets；只创建实际需要的资源。
3. 使用 system `skill-creator` 的初始化与验证工具；若项目工具不可用，再以同等目录结构创建。
4. 在 `.codex/skills/<name>/SKILL.md` 编写短入口；长代码、模板和平台步骤放入直接引用。
5. 将 Skill 加入 Manifest，运行路由和镜像验证。

创建前至少阅读 2～3 个相邻 Skill，并读取本项目真实代码模式。Tauri 后端示例必须保持 Command → Service → Database；前端示例必须通过 `src/lib/api/` 调用 IPC，并保持 Rust/TypeScript 类型一致。

## 修改

1. 先读取当前 `SKILL.md`、被引用的必要 references、Manifest 和路由用例。
2. 明确本次修改解决的触发、执行或准确性问题。
3. 若入口过长，先把原规则迁入同 Skill references，再压缩入口。
4. 保留安全禁令、错误分支、测试、构建和运行时验收条件。
5. 更新 description 时同步更新 Manifest 和正反向用例。
6. 验证 `agents/openai.yaml`（若存在）仍与入口一致。

不要为满足行数预算删除规则。可以合并重复表述，但必须保留一份可发现的权威规则。

## 重命名

重命名前解析所有引用和平台映射，确认没有同名冲突。完成以下原子变更：

- 将 `.codex/skills/<old>` 移到 `.codex/skills/<new>`。
- 修改 Frontmatter `name` 和目录名。
- 为新名称创建正式 Manifest 条目并移除旧条目，同时修改互斥、bundle 与路由引用。
- 修改测试用例、直接引用和命令映射。
- 同步脚本只创建新名称镜像，不会删除已变成 unlisted 的旧镜像或旧 command。
- 在用户明确授权删除精确旧目标后，逐个解析旧 `.claude/.agents` 镜像资源和生成 command，逐文件复核范围、符号链接与普通文件类型后安全删除；禁止用目录扫描推断删除权。
- 全局搜索旧名称，逐条判断是否为历史记录或遗漏引用。

删除旧路径属于破坏性动作；必须确认目标准确且用户已授权重命名。

## 删除

1. 证明 Skill 已废弃或被明确替代，并列出替代 Skill。
2. 检查 Manifest、bundles、测试、Hook、命令映射和其他 Skill 引用。
3. 在仍能从旧 Manifest 解析平台和命令映射时，列出规范源、每个镜像资源及生成 command 的精确路径，交由用户确认删除范围。
4. 获得删除授权后，逐个核对精确目标仍位于对应 Skill 目录、不是符号链接且是普通文件，再安全删除；同步器不会替整项删除提供授权。
5. 删除 `.codex` 规范源并移除 Manifest、bundle、测试和引用中的旧条目。
6. 运行同步与全量路由验证；unlisted、platform-local 和 upstream 文件不得因本次删除被顺带处理。

不得删除 upstream 管理 Skill、其他会话 WIP 或用户未授权的历史材料。Manifest 的新增、删除或 `managed` 字段不能单方面证明旧文件归本任务所有；禁止通过“扫描所有未列名目录”推断删除目标，未列管文件始终保留。优先使用可恢复方式，不执行宽泛递归删除。

## 内容迁移规则

- 入口保留：决策树、必须立即执行的安全规则、核心步骤、引用索引、完成条件。
- references 保留：完整模板、长代码示例、平台差异、FAQ、详细命令和检查表。
- scripts 承载：反复执行且需要确定性的校验、生成、转换与同步。
- assets 承载：输出时复制或加工、无需阅读的模板和二进制资源。

超过 100 行的 reference 增加目录；SKILL.md 直接链接，不建立多层引用链。
