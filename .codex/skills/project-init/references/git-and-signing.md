# Git、仓库与签名安全

## 本地 Git

- 新项目使用独立历史，并将模板设为 `upstream`。
- 不切换模板仓库分支，不污染模板工作区。
- 提交前逐文件暂存本流程生成的文件；禁止 `git add -A`、`git add .`。
- 提交、创建远端、push、tag 和发布是不同动作，不因初始化请求自动获得全部授权。

## 仓库可见性

源码主仓库默认且必须私有。通过任何平台 API 创建时明确设置私有；若用户要求公开源码，先说明源码、配置和业务逻辑暴露风险，再获得二次明确确认。

Updater/release 端点必须允许应用匿名 GET `update.json` 和安装包。若使用公开仓库，它只能包含发布产物、更新 manifest 和公钥，不能包含源码、私钥或凭据。使用 R2 等公开对象存储时仍需验证真实匿名 URL。

## 远端操作

Git 和仓库访问优先使用 Tauri SSH MCP。执行前解析并展示：平台、组织/用户名、仓库名、可见性、remote URL 和目标分支。成功后用只读查询验证，而不是只凭命令退出码。

禁止把 Token 拼进 URL、Node 命令、日志或文档。凭据从 Safe Credentials 或受控环境注入，不回显明文。

## 签名

- 生成密钥前确认保存位置和是否覆盖；已有目标绝不自动覆盖。
- 私钥保存在安全凭据或用户确认的受限路径，权限最小化，绝不提交 Git。
- 公钥可以写入 `tauri.conf.json`，但要验证与私钥配对。
- CI 通过安全 secret 注入 `TAURI_SIGNING_PRIVATE_KEY` 等值，不能写入 workflow 正文。
- 用户选择稍后配置时保留清晰占位符，并说明自动更新暂不可用。

## Updater 验证

1. 检查 `endpoints` URL 格式和 HTTPS。
2. 未带认证匿名读取实际 `update.json`。
3. 校验 manifest JSON、版本、平台产物 URL、签名字段和公钥。
4. 检查私有源码仓库与公开发布端点没有混用。
5. 真实客户端执行一次检查更新流程；HTTP 200 只是中间证据。

## 失败与回滚

- 远端创建失败：保留本地项目，报告错误，不循环重试写入。
- push 失败：不改写历史、不 force push，先核对权限、分支和 remote。
- 签名失败：不关闭签名校验，核对密钥格式和环境注入。
- 端点不可读：不将仓库改为公开源码，修复独立 release 端点或对象存储策略。
