# 项目信息采集与校验

## 必填输入

一次性收集并让用户确认：

1. 业务说明和目标用户。
2. 产品显示名称和 2～3 字母缩写。
3. 新项目目录名与 Rust/npm 包名。
4. Tauri 应用标识符。
5. 作者与项目描述。
6. 目标父目录和支持平台。

可选输入：开发/HMR 端口、现有远端仓库、Updater 端点、是否生成签名、需求/原型/品牌资产迁移。

## 格式校验

- 目标目录：解析为绝对路径，确认位于用户指定父目录下且不存在；不得使用根目录、HOME 或宽泛 glob。
- 包名：小写 snake_case，符合 Cargo/npm 当前约束；明确对应 lib 名 `<package>_lib`。
- identifier：小写反向域名，例如 `com.company.product`，不能只用显示名或含空格。
- 产品缩写：避免对整个仓库全局替换短字符串。
- URL：确认协议、仓库归属和匿名访问要求；不从样例推断真实用户名。
- 端口：扫描项目真实 Vite/Tauri 配置和当前监听情况，不能只套历史表格。

## 端口选择

读取 `vite.config.*`、`src-tauri/tauri.conf.json` 和 `package.json` 中的当前端口。扫描同级项目仅作为候选，最终需检查端口是否监听。不要为了占用冲突直接 kill 进程；改选端口或让用户处理现有服务。

HMR 端口可按项目现有约定分配，但必须验证不冲突并同步修改所有引用。

## 资产迁移选择

列出所有非空候选目录、文件数、目标路径和冲突。提供逐项选择：

- 不迁移（默认安全值）。
- 复制到新项目，保留模板原件。
- 移动到新项目，仅在用户明确要求清空模板临时资产时使用。

技能、Hooks、项目规范、个人凭据和未确认的跟踪文件永远不是可移动资产。

## 配置确认

创建目录前输出一份确认摘要：

```text
产品名称 / 缩写
包名 / lib 名 / identifier
模板提交 / 新目录
开发端口 / HMR 端口
源码仓库：未创建或私有目标
Updater：未配置或匿名可读端点
签名：稍后配置或安全路径
资产迁移：逐项目标与动作
```

推荐值必须标注为推荐；只有用户确认后才能进入写入阶段。
