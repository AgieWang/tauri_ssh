# Tauri SSH 需求文档：AI 时代的 SSH 工具

**版本**: V0.1 草案  
**日期**: 2026-06-19  
**项目路径**: `/Users/bin/Documents/GitHub/tauri_ssh`  
**参考对象**: 本机 Reeve App 0.4.0、Reeve 的受控远程运维/MCP 思路、传统 SSH/SFTP 客户端、Codex/Claude 类 AI 工具链  

---

## 1. 背景与定位

Tauri SSH 是一个面向 AI 时代的桌面 SSH 运维工具。它不是只做“终端连接 + 文件传输”的传统客户端，而是把 SSH、SFTP、服务器资产管理、AI 问答、命令审批、MCP 工具生态和审计记录整合到同一个本地桌面应用里。

核心目标：

- 让用户用自然语言理解服务器状态、生成命令、解释日志和排查问题。
- 让 AI 能协助操作服务器，但不能绕过用户设定的权限边界。
- 让服务器、凭据、分组、命令模板、文件传输和操作记录统一管理。
- 为后续接入 Codex、Claude、Cursor、MCP Host、团队审计和 Host Agent 模式留出架构空间。

一句话定位：

> 一个带 AI 权限闸门、MCP 扩展能力和 SFTP 文件管理的本地优先 SSH 运维工作台。

## 2. 用户画像

### 2.1 个人开发者

- 管理 3 到 20 台 VPS、云服务器、NAS 或内网机器。
- 常见需求是查看日志、重启服务、传文件、改配置、执行部署命令。
- 希望 AI 能解释命令和错误，但不希望 AI 自动执行危险操作。

### 2.2 小团队技术负责人

- 管理测试、预发、生产多套环境。
- 希望服务器按项目、环境、客户、区域分组。
- 需要操作审计、权限隔离、命令模板和风险提示。

### 2.3 AI 工具重度用户

- 已经使用 Codex、Claude、MCP、Reeve 或类似本地助手。
- 希望把服务器操作封装成 MCP 工具，让 AI 能读取状态、执行受控命令、查看文件或上传产物。
- 关注凭据不出本机、AI 看不到明文密码/私钥。

## 3. 产品原则

1. **本地优先**
   - 服务器清单、分组、连接配置、审计日志默认存储在本机 SQLite。
   - 凭据必须加密存储，优先走系统 Keychain/安全存储，不以明文进入前端状态。

2. **AI 受控而非放任**
   - AI 可以建议命令、解释输出、生成排查步骤。
   - AI 自动执行命令前必须经过策略引擎判断。
   - 高风险操作必须显式审批，禁止仅靠 prompt 约束。

3. **命令可追溯**
   - 谁发起、为什么发起、目标服务器、命令内容、审批状态、输出摘要、退出码都要记录。
   - 敏感输出需要脱敏后进入审计日志。

4. **MCP 是一等能力**
   - 应用既可以作为 MCP Host 管理外部 MCP Server，也可以作为 MCP Server 暴露受控 SSH 工具给 AI 客户端。
   - MCP 工具要继承同一套权限和审计规则。

5. **先直接 SSH，后扩展 Agent**
   - V0.1 先支持本机直连 SSH/SFTP。
   - V0.2 再考虑类似 Reeve/FJ Host Agent 的远端 Agent 模式，用于内网穿透、最小化集中凭据、日志/文件代理。

## 4. 总体范围

### 4.1 V0.1 必做

- SSH 服务器分组管理。
- 服务器连接配置 CRUD。
- `~/.ssh/config` 导入和解析，至少支持 Host、HostName、Port、User、IdentityFile。
- 凭据管理：密码、私钥、passphrase 的安全存储抽象。
- SSH 终端连接。
- 命令执行和输出流式展示。
- 日志监听：支持标签多开，同时 tail 同一或不同服务器的多个文件。
- SFTP 文件浏览、上传、下载、删除、重命名、内置文本编辑器。
- AI 命令行问答：围绕当前服务器、当前目录、最近命令输出进行问答。
- AI 命令建议：AI 生成命令但默认不直接执行。
- AI Provider 首版支持 OpenAI API、DeepSeek、GLM、Kimi、MiniMax，并预留兼容 OpenAI API 的自定义 Provider。
- AI 权限控制：只读、需确认、禁止、审批队列四类策略。
- MCP Server 基础能力：暴露服务器列表、只读探测、受控命令执行、SFTP 读写工具。
- 操作审计日志。
- 团队/多用户能力 V0.1 先预留字段和审计维度，不实现完整团队协作。
- macOS 和 Windows 同步作为首发平台。

### 4.2 V0.2 应做

- 命令模板库和变量化执行。
- 多服务器批量执行。
- 服务器健康仪表盘：CPU、内存、磁盘、端口、进程、服务状态。
- AI 任务模式：让 AI 分步骤排查，但每步仍受权限控制。
- MCP Client 管理：添加外部 MCP Server，测试工具，管理 token/header。
- 文件传输队列、断点续传、冲突处理。
- Linux 桌面端适配和验证。
- Host Agent 模式设计与原型。

### 4.3 V1.0 可选

- 团队空间、角色权限、操作审批流。
- 云同步服务器清单，但凭据仍本地或企业密钥库保存。
- 多模型 Provider：OpenAI、Anthropic、本地模型、兼容 OpenAI API 服务。
- 远程日志 Tail、应用部署流水线、服务编排。
- 录屏式终端回放和事故复盘。

## 5. 核心场景

### 5.1 添加服务器并连接

用户打开“服务器”页面，点击新增服务器，填写：

- 名称：`prod-api-01`
- 分组：`生产 / API`
- Host：`10.0.0.12`
- 端口：`22`
- 用户名：`root`
- 认证方式：密码或私钥
- 标签：`prod`、`api`、`linux`

保存后应用执行连接测试。测试成功后，用户可打开终端标签页。

验收标准：

- 新增服务器后出现在对应分组树中。
- 用户可以从 `~/.ssh/config` 导入服务器配置，并在导入前预览识别结果。
- 凭据不出现在前端明文、日志、审计记录。
- 连接失败时显示可理解的错误原因，例如认证失败、超时、Host key 不匹配。

### 5.2 AI 解释服务器状态

用户在终端中执行：

```bash
df -h
free -m
systemctl status nginx
```

随后在右侧 AI 面板提问：

> 这台机器现在有什么风险？

AI 根据最近命令输出解释磁盘、内存和 nginx 状态，并给出下一步建议。默认只生成建议，不执行命令。

验收标准：

- AI 上下文包含用户允许的终端输出片段。
- 敏感行先脱敏再传给 AI。
- AI 回复中如果包含命令，命令以“建议命令”形式展示，用户可复制或点击“申请执行”。

### 5.3 AI 受控执行命令

用户输入：

> 帮我查看 8080 端口是谁占用的。

AI 生成：

```bash
lsof -i :8080
```

策略引擎判断为只读命令，允许直接执行或一键确认执行。执行结果流式返回，并写入审计。

如果 AI 生成：

```bash
rm -rf /var/log/*
```

策略引擎命中危险命令，直接拒绝，给出原因和更安全替代方案。

验收标准：

- 策略不是 prompt 文案，而是本地代码规则。
- 危险命令即使来自用户请求也要拦截或二次确认。
- 审计记录区分“AI 建议”“用户确认”“系统执行”。

### 5.4 SFTP 上传文件

用户打开服务器文件管理，进入 `/opt/app/upload`，拖入本地文件。应用显示上传队列、进度、速度、失败原因。

验收标准：

- 支持上传、下载、删除、重命名、新建目录。
- 默认禁止覆盖，冲突时询问：跳过、覆盖、重命名。
- 上传目标路径可受服务器级策略限制。
- 大文件上传不阻塞 UI。

### 5.5 MCP 接入 AI 客户端

用户在“AI / MCP”页面启用本应用的 MCP Server。Codex 或 Claude 可看到工具：

- `list_servers`
- `system_info`
- `ssh_exec`
- `sftp_list`
- `sftp_read`
- `sftp_write`
- `tail_log`

AI 调用工具时，Tauri SSH 后端执行策略检查和审计，必要时弹出审批。

验收标准：

- MCP 调用和用户 UI 操作走同一套 Service 权限和审计逻辑。
- AI 客户端拿不到明文凭据。
- 审批中、拒绝、超时、执行失败都有结构化返回。

### 5.6 多标签日志监听

用户打开“日志监听”页面，选择一台或多台服务器，添加需要监听的日志文件：

- `prod-api-01:/opt/app/logs/app.log`
- `prod-api-01:/var/log/nginx/error.log`
- `prod-worker-02:/opt/worker/logs/job.log`

每个监听目标以独立标签页展示。用户可以同时打开同一服务器的多个文件，也可以跨服务器打开多个日志文件。每个标签维护独立的连接状态、滚动位置、搜索条件、过滤条件、关键词高亮、暂停/继续状态。

验收标准：

- 同一服务器多个日志文件可以并发监听，互不阻塞。
- 不同服务器多个日志文件可以并发监听，单个连接失败不影响其他标签。
- 支持暂停、继续、清屏、自动滚动、关键词搜索、关键词过滤和高亮。
- 搜索用于在已接收日志缓冲中定位匹配行，支持匹配计数、上一条/下一条跳转。
- 过滤用于实时隐藏不匹配的新旧日志行，关闭过滤后恢复完整缓冲显示。
- 支持把当前标签最近 N 行发送给 AI 解释。
- 支持 MCP `tail_log` 工具读取日志，且走同一套只读权限和审计。
- 日志内容脱敏后进入 AI 上下文和审计摘要。

## 6. 功能需求

### 6.1 服务器分组管理

功能：

- 分组树：支持多级分组。
- 服务器列表：支持搜索、标签筛选、状态筛选。
- 分组操作：新增、重命名、删除、移动服务器。
- 服务器字段：名称、Host、端口、用户名、认证方式、默认目录、标签、备注、风险等级、环境类型。

建议数据模型：

- `server_groups`
  - `id`
  - `parent_id`
  - `name`
  - `sort_order`
  - `created_at`
  - `updated_at`
- `servers`
  - `id`
  - `group_id`
  - `workspace_id`
  - `owner_user_id`
  - `alias`
  - `host`
  - `port`
  - `username`
  - `auth_type`
  - `credential_ref`
  - `default_path`
  - `environment`
  - `tags_json`
  - `notes`
  - `source_type`: `manual` / `ssh_config` / `import`
  - `created_at`
  - `updated_at`

### 6.2 凭据管理

功能：

- 支持密码、私钥、私钥 passphrase。
- 必须支持引用和导入本地 `~/.ssh/config`。
- 导入 `~/.ssh/config` 时展示 Host 解析结果，允许用户逐项选择导入。
- 支持引用本地 `~/.ssh/id_*`，但导入前提示风险。
- 支持凭据测试、轮换、删除。
- 凭据详情默认不可见，必要时只能通过系统授权短时查看。

安全要求：

- 前端不得持久化明文凭据。
- 后端日志和审计日志不得输出明文凭据。
- MCP 工具不得返回凭据值。
- V0.1 使用 SQLite 存储凭据元数据和加密后的 secret payload。
- 加密密钥不得硬编码在源码中；macOS/Windows 首发阶段至少要设计系统密钥链或用户主密码派生方案。

### 6.3 SSH 终端

功能：

- 多标签终端。
- 每个标签绑定一个服务器会话。
- 支持复制、粘贴、清屏、断开、重连。
- 支持命令历史记录和会话输出摘要。
- 支持终端输出选择后发送给 AI 解释。

技术建议：

- 前端终端使用 `xterm.js`。
- Rust 后端使用 `russh` 或 `ssh2` 维护会话。
- 输出通过 Tauri event 流式推送到前端。

### 6.4 命令执行与模板

功能：

- 单命令执行：输入命令，返回 stdout/stderr/exit code。
- 流式输出：长命令实时显示。
- 超时控制：默认 30s，可配置。
- 非交互建议：AI 生成命令时提示补充 `-y`、`--quiet` 等非交互参数。
- 命令模板：保存常用命令，支持变量和服务器分组批量执行。

命令风险分级：

| 等级 | 说明 | 示例 | 默认处理 |
|------|------|------|----------|
| L0 | 只读探测 | `uname -a`, `df -h`, `ps aux` | 可直接执行或轻确认 |
| L1 | 低风险变更 | 创建临时目录、查看日志 tail | 用户确认 |
| L2 | 服务变更 | `systemctl restart nginx`, 修改配置 | 审批或二次确认 |
| L3 | 高风险破坏 | `rm -rf`, `mkfs`, `iptables -F` | 默认拒绝 |
| L4 | 凭据/隐私读取 | `cat /etc/shadow`, grep 密钥 | 默认拒绝 |

### 6.5 日志监听

功能：

- 支持多标签监听远程日志文件。
- 一个标签绑定一个监听目标：`server_id + path + session_id`。
- 支持同一服务器多文件同时监听。
- 支持不同服务器多文件同时监听。
- 支持新增标签、关闭标签、重连标签、暂停/继续、清屏、自动滚动。
- 支持关键词搜索：在当前标签已接收日志缓冲中查找，显示匹配数量，支持上一条/下一条跳转。
- 支持关键词过滤：仅展示匹配关键词的日志行，支持实时流式过滤。
- 支持关键词高亮、错误级别高亮。
- 搜索和过滤支持大小写敏感开关、正则模式开关、反向过滤开关。
- 支持保存常用日志路径，并可从服务器应用配置中快速选择。
- 支持将当前标签最近 N 行发送给 AI 解释。
- 支持监听状态：connecting、tailing、paused、reconnecting、failed、closed。

权限：

- 日志监听属于只读能力。
- 监听路径必须经过服务器级 allowed read paths 校验。
- 默认禁止监听敏感文件：`/etc/shadow`、私钥文件、凭据文件。
- MCP `tail_log` 和 UI 日志监听共用同一套路径校验、脱敏和审计。

技术建议：

- Rust 后端为每个日志标签维护独立 tail session。
- 输出通过 Tauri event 按 `tail_session_id` 推送到前端。
- 前端用虚拟列表渲染日志行，避免长时间监听导致 DOM 过大。
- 标签关闭时必须释放远端 tail 进程和本地事件订阅。
- 网络抖动时按标签单独重连，不能全局断开。

建议数据模型：

- `log_tail_sessions`
  - `id`
  - `server_id`
  - `path`
  - `title`
  - `status`
  - `filter_keyword`
  - `search_keyword`
  - `search_options_json`
  - `highlight_rules_json`
  - `auto_scroll`
  - `created_at`
  - `closed_at`
- `log_tail_presets`
  - `id`
  - `server_id`
  - `name`
  - `path`
  - `tags_json`
  - `created_at`

### 6.6 SFTP 文件管理

功能：

- 远程目录浏览。
- 上传、下载、删除、重命名、新建目录。
- 文件预览：文本文件、日志文件。
- 内置文本编辑器：V0.1 必须支持远程文本文件打开、编辑、保存回传。
- 编辑器基础能力：编码检测、换行符保留、未保存提示、保存前差异预览。
- 传输队列：进度、速度、剩余时间、失败重试。

权限：

- 每台服务器可配置允许读写路径。
- 默认敏感路径只读或禁止：`/etc/shadow`、`/root/.ssh`、系统关键目录。
- AI 触发的写文件操作必须走审批。

### 6.7 AI 命令行问答

功能：

- 右侧 AI 面板，围绕当前服务器、当前会话、选中输出对话。
- Provider 配置：OpenAI API、DeepSeek、GLM、Kimi、MiniMax、自定义 OpenAI-compatible Endpoint。
- 每个 Provider 支持独立 API Key、Base URL、模型名、温度、超时和启用状态。
- 支持三类问题：
  - 解释：解释错误日志、命令输出、配置片段。
  - 建议：给出排查步骤和命令。
  - 执行申请：把建议命令提交给策略引擎。
- 支持上下文开关：
  - 最近 N 条命令。
  - 当前终端选中内容。
  - 当前服务器基本信息。
  - 当前 SFTP 路径。

AI 输出要求：

- 命令和解释分区展示。
- 命令默认不自动执行。
- 涉及破坏性操作时，必须先解释风险和回滚方案。

Provider 首版要求：

| Provider | V0.1 要求 | 备注 |
|----------|-----------|------|
| OpenAI API | 必做 | 支持官方 Chat/Responses 兼容封装，具体 API 形态实现前再确认 |
| DeepSeek | 必做 | 按 OpenAI-compatible 接口优先适配 |
| GLM | 必做 | 支持智谱 GLM 模型配置 |
| Kimi | 必做 | 支持 Moonshot/Kimi 模型配置 |
| MiniMax | 必做 | 支持 MiniMax 模型配置 |
| 自定义 Provider | 必做 | 支持用户填写 Base URL、API Key、模型名 |

安全要求：

- AI Provider Key 使用与 SSH 凭据同等级的加密存储策略。
- Provider Key 不进入审计明文，不传给 MCP 客户端。
- AI 请求日志默认只记录 provider、model、耗时、token 用量和脱敏后的摘要。

### 6.8 AI 权限控制

权限模型：

- **全局策略**：控制 AI 默认能力。
- **服务器策略**：不同服务器可设置不同权限。
- **分组策略**：生产分组更严格，测试分组更宽松。
- **工具策略**：MCP 工具、终端命令、SFTP 写入分别控制。

策略档位：

| 档位 | 说明 |
|------|------|
| 禁用 AI 执行 | AI 只能问答和生成建议 |
| 只读自动 | 只读命令可自动执行，变更需确认 |
| 变更需审批 | 所有变更进入审批队列 |
| 受信任模式 | 低风险变更可执行，高风险仍拦截 |

审批队列：

- 展示发起来源：用户点击、AI 申请、MCP 调用。
- 展示目标服务器、命令、风险等级、AI 理由。
- 支持允许一次、拒绝、允许同类命令 N 分钟。
- 审批结果进入审计日志。

### 6.9 MCP 能力

#### 6.9.1 作为 MCP Server

向外部 AI 客户端暴露工具：

| 工具 | V0.1 | 说明 |
|------|------|------|
| `list_servers` | 必做 | 返回用户允许 AI 看到的服务器别名和元信息 |
| `system_info` | 必做 | 执行只读系统信息采集 |
| `port_check` | 必做 | 检查端口监听 |
| `service_status` | 必做 | 查询服务状态 |
| `ssh_exec` | 必做 | 受控执行命令 |
| `tail_log` | 必做 | 实时读取日志，可对接日志监听标签 |
| `sftp_list` | 必做 | 列目录 |
| `sftp_read` | 必做 | 读取小文件或片段 |
| `sftp_write` | 应做 | 写入文件，默认审批 |
| `sftp_upload` | 应做 | 上传本地文件，默认审批 |

#### 6.9.2 作为 MCP Client

管理外部 MCP Server：

- 添加 HTTP / stdio MCP Server。
- 配置 headers / token 引用。
- 测试连接和列工具。
- 给外部 MCP 工具配置“可被本应用 AI 调用”的权限。

V0.1 可以先只做 MCP Server；MCP Client 放 V0.2。

### 6.10 审计与日志

审计对象：

- 服务器 CRUD。
- 凭据创建、更新、删除，但不记录明文。
- SSH 连接、断开。
- 日志监听打开、暂停、继续、关闭、失败。
- 命令建议、审批、执行、失败。
- SFTP 上传、下载、删除、重命名。
- MCP 工具调用。
- AI 问答摘要。

审计字段：

- `id`
- `timestamp`
- `actor_type`: `user` / `ai` / `mcp_client` / `system`
- `actor_name`
- `server_id`
- `action_type`
- `risk_level`
- `approval_status`
- `command_preview`
- `output_summary`
- `exit_code`
- `duration_ms`
- `error_message`

脱敏规则：

- 密码、token、私钥、passphrase、`Authorization` header 默认脱敏。
- 命令输出中出现疑似密钥、密码行时脱敏。
- 脱敏后的占位符不得被当作真实凭据再次写入配置。

## 7. 非功能需求

### 7.1 安全

- 凭据本地加密保存。
- AI 和 MCP 不直接接触明文凭据。
- 高风险命令硬拦截，不允许通过提示词绕过。
- 支持 Host Key 校验和变更告警。
- 审计日志可导出但默认脱敏。

### 7.2 稳定性

- SSH 连接异常断开后可重连。
- 日志监听单标签失败不影响其他标签。
- 长命令输出不能卡死 UI。
- SFTP 大文件传输要有取消和失败重试。
- MCP 调用要有超时和结构化错误。

### 7.3 性能

- 服务器列表 1000 条内搜索和筛选无明显卡顿。
- 终端输出使用增量渲染。
- 日志监听使用虚拟列表和行数上限策略。
- 文件传输使用分片和后台任务。
- 内置文本编辑器 V0.1 面向小到中等文本文件；超过阈值时只读预览并提示下载编辑。
- 审计日志分页查询。

### 7.4 跨平台

- macOS 和 Windows 作为 V0.1 首发平台，必须同步验证 SSH/SFTP、凭据加密、终端渲染、SFTP 编辑器和 MCP Server。
- Linux 桌面端作为 V0.2 适配目标。
- 系统 Keychain 抽象需要平台适配。
- 文件路径、换行、权限展示需跨平台处理。

## 9. 推荐技术方案

### 9.1 方案 A：本地直连 SSH 优先（推荐 V0.1）

描述：

- Tauri 后端直接通过 SSH crate 连接目标服务器。
- 所有权限、审计、AI 调用和 MCP 工具都在本机应用内完成。

优点：

- 架构清晰，开发最快。
- 不需要远端安装 Agent。
- 适合个人用户和早期 MVP。

缺点：

- 所有 SSH 凭据集中在本机。
- 内网机器需要用户本机可达。
- 团队协作和代理能力有限。

### 9.2 方案 B：Reeve/Host Agent 模式

描述：

- 本机应用作为控制端。
- 目标机器或内网跳板安装轻量 Agent。
- Agent 主动连回控制端，负责执行本机命令、文件传输、日志读取。

优点：

- 更适合内网、生产和团队场景。
- 可以减少集中 SSH 凭据暴露。
- 日志 tail、上传、服务检测可以本地化执行。

缺点：

- 需要额外安装和升级 Agent。
- WebSocket 连接、心跳、注册、版本兼容更复杂。
- V0.1 做会拖慢首版。

### 9.3 方案 C：纯 MCP 外壳

描述：

- 应用主要作为 MCP 管理器和 UI 壳，把 SSH 能力交给外部 MCP Server。

优点：

- 生态弹性高。
- 可快速接入已有工具。

缺点：

- 权限和审计难以统一。
- 用户初始配置复杂。
- 难保证凭据安全边界。

### 9.4 推荐结论

V0.1 采用方案 A：本地直连 SSH 优先。  
V0.2 引入方案 B：Host Agent 模式。  
方案 C 只作为扩展能力，不作为核心架构。

- `audit_logs` 保存输出摘要，不保存完整大输出；完整输出可选存文件并受保留期控制。

## 12. 验收标准

V0.1 完成时，必须能完成以下闭环：

1. 新增一台 SSH 服务器并通过连接测试。
2. 打开终端并执行 `pwd`、`df -h`、`systemctl status <service>`。
3. 让 AI 解释最近命令输出。
4. 让 AI 生成一条只读命令，并由用户确认执行。
5. 让 AI 生成一条危险命令，系统必须拦截。
6. 同时打开至少 3 个日志监听标签，覆盖同一服务器两个文件和另一台服务器一个文件。
7. 暂停其中一个日志标签，其他标签仍持续输出。
8. 在某个日志标签中搜索 `ERROR`，看到匹配数量并可跳转上一条/下一条。
9. 开启关键词过滤后只显示匹配行，关闭过滤后完整日志缓冲恢复显示。
10. 让 AI 解释某个日志标签最近 N 行。
11. 通过 SFTP 上传一个文件到允许目录。
12. 在审计页面查到这次终端命令、日志监听、搜索过滤、AI 建议、审批和文件上传。
13. 通过 MCP 客户端调用 `list_servers`、一个只读探测工具和 `tail_log`。

## 13. 待确认问题

当前已确认：

1. V0.1 必须支持 `~/.ssh/config` 导入。
2. AI Provider 首版必须支持 OpenAI API、DeepSeek、GLM、Kimi、MiniMax，并支持自定义 OpenAI-compatible Endpoint。
3. MCP 首版优先做“本应用作为 MCP Server”，MCP Client 管理放到 V0.2。
4. 凭据安全首版使用 SQLite 存储加密后的 secret payload。
5. 需要团队/多用户能力，V0.1 先预留字段和审计维度。
6. SFTP 首版必须包含内置文本编辑器。
7. macOS 和 Windows 同步作为首发平台。

后续仍需细化：

1. `~/.ssh/config` 导入是否需要支持 ProxyJump、ProxyCommand、Include。
2. SQLite 加密密钥采用系统 Keychain 包装，还是用户主密码派生。
3. OpenAI API 首版使用 Chat Completions、Responses API，还是内部统一抽象后按 Provider 适配。
4. 内置文本编辑器首版文件大小上限、编码支持范围和冲突检测策略。
5. Windows 首发是否必须支持 Pageant / OpenSSH Agent / Windows Credential Manager。
