# 16 可观测、测试与验收确认

- 状态：Proposed
- 对应用户需求：全部功能的完成判定

## 1. 指标体系

### 数据覆盖

按项目、版本、仓库和格式记录：发现、成功解析、部分解析、跳过、失败、全文索引、向量化和建图数量及原因。

### 检索/问答质量

- 标题命中率、Recall@K、MRR。
- 引用准确率、版本串用率。
- 证据不足拒答率、冲突识别率。
- 回答延迟和可打开引用比例。

### 任务与资源

- 排队/运行时长、重试、失败阶段、吞吐。
- SQLite/资产增长、向量构建耗时、图谱规模。
- 前台搜索和问答 P50/P95、内存峰值。

## 2. 验证分层

| 层级 | 证明什么 | 不证明什么 |
|---|---|---|
| 格式化/类型/构建 | 代码可通过静态工具 | 真实功能可用 |
| 单元/契约测试 | 局部规则、DTO、解析器 | 完整桌面链路 |
| 数据库测试 | 迁移、DAO、约束 | 页面与外部能力 |
| Tauri IPC | 真实 Command 契约 | 浏览器用户体验 |
| 浏览器 | 真实交互、状态、控制台 | 原生权限或模型推理（若走 mock） |
| 本机端到端 | 文件→任务→索引→引用→回答 | 生产/所有平台 |
| 回环 Provider | 远程协议、安全和失败路径 | 真实第三方服务质量 |
| 目标平台打包 | macOS 依赖与运行 | Windows/Linux（除非另测） |

## 3. 必测数据集

- 4 个微服务仓库，共享 Tag、不同 Tag、分支移动、脏工作树和中文路径。
- Markdown、HTML 原型、DOCX、XLSX、PPTX、PDF、图片及各类损坏/恶意输入。
- 同名标题、版本号、类名、路由、表字段和自然语言同义问题。
- 文档冲突、失败测试、后续版本变化、无证据问题和敏感片段。

## 4. 阶段门禁

每项能力只有在相关静态、测试、数据库、IPC、浏览器、本机端到端、安全和性能证据均完成后才标记“已验收”。未覆盖层级必须显示为“未验证”，不能用构建通过替代。

## 5. 推荐目标

| 指标 | 首期目标 |
|---|---:|
| 标题搜索 P95 | ≤ 50ms |
| 全文搜索 P95 | ≤ 100ms |
| 版本串用率 | 0 |
| 可验证事实引用率 | 100% |
| 无证据问题明确拒答 | 100% |
| 长任务重复执行产生重复正式结果 | 0 |
| 敏感内容外发/日志泄漏 | 0 |

准确率类指标需要在确认的固定评测集上建立基线，不能只写抽象百分比。

## 6. 交付检查

- Rust/TypeScript 格式化。
- 聚焦测试、类型检查、必要构建和 `git diff --check`。
- 新页面使用 Codex 内置浏览器或 Control Chrome 验收。
- 数据迁移使用副本验证，保留迁移前后数量。
- 安全审查覆盖路径、HTML/Office、远程请求、凭据和审计。
- 运行时/生产未验证项在交付说明中单独列出。

## 7. 请确认

- **C16-2（推荐）**：版本串用率和敏感泄漏目标均为 0。
- **C16-3（推荐）**：远程协议以本机回环 Provider 作为完成门禁，真实外部服务另做集成验收。
- **C16-4（推荐）**：每次模型/Profile 变更必须复跑同一评测集。
