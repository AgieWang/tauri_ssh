# 01 产品信息架构与用户旅程确认

- 状态：Proposed
- 对应用户需求：1、3、6、11

## 1. 推荐信息架构

```text
团队知识库
  ├─ 项目列表
  │   └─ 项目工作台
  │       ├─ 概览
  │       ├─ 代码仓库
  │       ├─ 项目版本
  │       ├─ 文档
  │       ├─ 搜索
  │       ├─ 代码分析
  │       ├─ 知识图谱
  │       └─ AI 问答
  ├─ 处理任务
  └─ 知识库设置
```

主界面始终显示当前项目和当前版本。普通操作继承上下文，不重复要求用户选择；跨项目、跨版本功能必须由用户显式开启。

## 2. 六条线性主流程

### 首次创建项目

创建项目 → 选择多个仓库 → 选择推荐版本 → 确认并开始同步。

### 上传文档

选择文件 → 自动识别标题/格式 → 确认项目与版本 → 加入处理队列 → 查看结果。

### 手工维护文档

新建草稿 → 编辑 → 保存草稿 → 提交说明 → 生成正式版本。

### 搜索知识

输入关键词 → 查看标题/正文命中 → 打开文档与精确位置 → 按需展开高级筛选。

### AI 代码分析

选择项目版本 → 确认仓库和范围 → 查看分析进度 → 审阅草稿与证据 → 编辑并确认入库。

### 项目问答

继承项目/版本 → 输入问题 → 查看有引用的回答 → 打开证据；范围不清时先让用户选择。

## 3. 路由建议

| 路由 | 页面职责 |
|---|---|
| `/knowledge/projects` | 项目目录和首次使用入口 |
| `/knowledge/projects/:id/overview` | 状态、风险、下一步 |
| `/repositories` | 仓库绑定、可用性、同步 |
| `/versions` | 项目版本清单和完整度 |
| `/documents` | 文档列表、创建、上传、历史 |
| `/search` | 基础搜索和高级筛选 |
| `/analysis` | 分析任务和草稿审核 |
| `/graph` | 有界图谱与证据 |
| `/qa` | 基于证据问答 |
| `/knowledge/jobs` | 统一任务中心 |
| `/knowledge/settings` | Provider、向量、安全、配额 |

## 4. 页面状态约定

每个页面必须分别处理：首次加载、空数据、可重试错误、正常数据、提交中、成功、部分成功、取消和无权限。长任务立即创建可见任务，禁止按钮点击后无反馈。

## 5. 实施拆分

1. 保持 `/knowledge` 入口，重定向项目列表。
2. 建立项目工作台布局和项目/版本上下文。
3. 按路由逐域迁移页面，旧单页只作为回滚壳。
4. 所有菜单、单选、多选和状态使用中文标签，内部枚举值不变。
5. 用真实浏览器验证返回、刷新、深链接、空/错/成功态和最小窗口布局。

## 6. 验收标准

- 首次用户四步内完成项目初始化。
- 常用流程默认页面不显示内部 ID、指纹、维度、checkpoint 等技术字段。
- 返回上一步、关闭弹窗或提交失败不会丢失用户输入。
- 任何异步动作都有当前状态、结果和下一步。

## 7. 请确认

- **C01-1（推荐）**：采用“项目工作台 + 独立领域路由”，不继续扩展大 Tabs 单页。
- **C01-2（推荐）**：项目和版本作为全局可见上下文，普通操作自动继承。
- **C01-3（推荐）**：跨项目/跨版本查询默认关闭，必须显式开启。
- **C01-4（推荐）**：旧知识页面仅保留短期回滚，不作为新页面交互参考。
