# 05 标题与全文搜索确认

- 状态：Proposed
- 对应用户需求：4

## 1. 搜索层级

1. 标题精确匹配。
2. 标题前缀和包含匹配。
3. 全文 FTS5 匹配。
4. 可选向量语义召回。
5. 可选已确认图谱关系扩展。

标题与全文是基础能力；向量或图谱不可用时不得影响基础搜索。

## 2. 查询范围

所有通道在排序前统一应用：项目、项目版本、仓库、Git 快照、文档类型、来源、状态、标签和权限过滤。草稿、软删除、解析失败正文和未授权内容不得进入正式结果。

## 3. 排序与去重

推荐首期使用规则融合：标题精确 > 标题前缀 > 标题包含 > 正文；可选通道用 RRF 合并。每个结果展示命中通道和业务摘要，不在默认界面暴露内部得分。

同一逻辑文档的多个通道命中合并为一项，引用落到具体文档版本和结构位置。

## 4. 分页契约

- 使用稳定排序键和游标，不用不稳定的大 offset 作为长期协议。
- 游标绑定查询条件和结果快照标识。
- 索引在分页期间变化时，继续旧快照或明确提示“结果已更新”。
- 默认页大小 50，可配置上限 100。

## 5. 当前状态

- 旧实现已有 FTS 和混合检索基础。
- schema v39 已有标题索引表，但任务清单中的标题回填、硬过滤、稳定分页、解释和新搜索页面尚未完成。
- 需要避免把已有旧检索 API 直接当作新搜索契约已闭环。

## 6. 实施任务

1. 建标题规范化字段和回填任务。
2. FTS 只索引已提交且当前可见的文档版本。
3. 统一搜索请求/结果 DTO、错误码和游标。
4. 实现安全高亮，禁止把命中 HTML 当可信内容渲染。
5. 新建单搜索框页面，高级筛选默认折叠。
6. 对中文标题、版本号、路径、类名、接口路由和 Office 表格内容做评测。

## 7. 验收标准

- 精确标题稳定排在仅正文命中前。
- 查询旧版本不会出现新版本内容。
- 无向量模型时仍可完整搜索。
- 图片无 OCR 时只支持标题/元数据，页面明确说明未索引正文。
- P95 目标：标题不高于 50ms，全文不高于 100ms（代表性本机语料）。

## 8. 请确认

- **C05-1（推荐）**：标题与全文为强制基础，向量和图谱仅增强。
- **C05-2（推荐）**：结果默认按业务匹配类型解释，不显示内部浮点得分。
- **C05-3（推荐）**：采用稳定游标分页，默认 50 条。
- **C05-4（推荐）**：跨项目/版本搜索放到高级筛选并需要显式确认。
- **C05-5（待选择）**：标题包含检索采用独立 trigram FTS5 表；推荐接受，普通索引保留精确/前缀降级。
