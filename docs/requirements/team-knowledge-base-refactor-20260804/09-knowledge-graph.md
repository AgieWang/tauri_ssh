# 09 项目知识图谱确认

- 状态：Proposed
- 对应用户需求：8

## 1. 图谱定位

图谱是可重建的派生投影，不是项目事实的唯一存储。原始文档、代码元素、已确认关系和证据引用继续由各来源表负责；统一投影用于跨来源查询和展示。

## 2. 首期节点与关系

| 节点 | 示例关系 |
|---|---|
| 项目、仓库、项目版本 | 包含、发布于、演进到 |
| 文档、章节、需求 | 描述、实现、验证、引用 |
| 代码元素、模块、API/IPC | 调用、实现、依赖、暴露 |
| 数据库表/字段、配置项 | 读、写、配置、约束 |
| 测试用例/结果 | 验证、失败于、覆盖 |

实体键必须包含项目和版本范围；不得仅按同名自动合并不同版本实体。

## 3. 关系可信度

- 确定性关系：由解析器/静态分析直接得到，可标记来源算法和证据。
- 人工确认关系：用户新增或确认，优先用于默认图谱与问答。
- AI 建议关系：默认未确认，不进入默认检索扩展。

## 4. 构建与查询

- 按项目版本、来源哈希和投影版本增量构建。
- 新构建完成校验后原子激活，失败保留旧图谱。
- 默认查询当前实体的一层已确认关系。
- 支持方向、关系类型、确认状态、深度和节点/边上限。
- 默认最多 1,000 节点，硬上限 5,000；超限要求筛选或继续展开。

## 5. 展示建议

主视图采用 Canvas 有界子图，右侧提供可访问的关系列表和证据详情。默认标签全部中文；技术实体原名作为副标题。用户点击边可重新打开精确文档或代码证据。

## 6. 当前状态

schema 已有图谱构建、节点和边表，旧实现已有文档/代码关系；新图谱查询 Command/Service 仍主要为空骨架。统一投影、版本隔离、关系确认和真实页面仍待实现。

## 7. 验收标准

- 同名类在两个版本中不会错误合并。
- 构建失败不影响已激活图谱。
- AI 建议边默认不可用于事实回答。
- 节点/边都能打开稳定证据；无证据边被隔离。
- 键盘可选择节点、缩放和查看关系列表。
