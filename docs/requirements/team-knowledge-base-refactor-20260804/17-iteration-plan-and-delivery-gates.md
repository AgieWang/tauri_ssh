# 17 迭代路线、依赖与交付门禁确认

- 状态：Proposed
- 对应用户需求：实施顺序与完成定义

## 1. 推荐实施策略

采用“兼容 Facade + 领域切片 + 阶段开关”，每个阶段交付一条可运行闭环，不按前端/后端横向大批拆分。保留旧入口回滚，但不继续扩展旧 UI。

## 2. 阶段规划

| 阶段 | 目标闭环 | 主要产物 | 退出门禁 |
|---|---|---|---|
| P0 基线确认 | 文档、决策、契约和数据基线 | 本确认包、任务映射、固定夹具 | 用户确认关键 C 项 |
| P1 目录/文档 | 项目、多仓库、版本、手工/上传文档 | 新工作台骨架、CRUD、资产 | 浏览器+IPC+迁移闭环 |
| P2 多格式/搜索 | Office/HTML/PDF 接入与标题/全文 | 解析注册表、搜索页 | 恶意夹具、P95、引用位置 |
| P3 版本/分析 | 多仓库版本完整度与 AI 草稿审核 | 快照读取、分析草稿、确认入库 | 不修改仓库、引用有效 |
| P4 图谱 | 版本化投影和证据图谱 | 构建/查询/确认/UI | 隔离、上限、可访问性 |
| P5 向量/问答 | 本地向量、远程协议和证据问答 | Profile、检索融合、QA | 本机推理/回环、拒答/冲突 |
| P6 收口 | 评测、迁移、回滚和旧入口收口 | 门禁报告、兼容计划 | 全链路无 P0/P1 缺陷 |

## 3. 每阶段最小提交单元

1. 契约/类型和测试。
2. Database/迁移及副本验证。
3. Service/Command 和 IPC。
4. React 页面与状态。
5. 浏览器和真实 Tauri 闭环。
6. 安全/性能/差异检查。

同一单元完成后再移动下一域，减少兼容 Facade 双写时间。

## 4. 依赖决策

- Office/HTML/PDF 解析依赖：先锁定已通过许可证、安全和 macOS 构建检查的版本。
- OCR：本地适配器可选注册；缺失不阻断非图片文档。
- 图谱：首期不引入远程图数据库。
- 向量：首期不引入远程向量存储；具体本地模型保持可替换。
- 前端：优先现有 Ant Design/Tailwind/设计令牌，不引入重型可视化依赖前先验证包体和无障碍。

## 5. 上线与回滚

- 各域独立功能开关：目录、文档、解析、搜索、分析、图谱、向量、问答。
- 新构建索引/图谱/Profile 校验后原子激活。
- 关闭新域时回到旧 Facade/旧活动索引，不降级数据库。
- 原始资产和不可变版本不随派生功能回滚删除。
- 旧 UI 只在隔离开关中短期保留，删除另立任务和审批。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 当前工作区多会话并发 | 单文件占用检查、独立模块、小步修改、不 stash/reset |
| 旧/新 API 漂移 | 显式 DTO、兼容契约测试、单一委托 |
| 解析器包体/漏洞 | 可选注册、锁文件审计、恶意夹具 |
| 大库启动缓慢 | 大回填全部后台任务化 |
| 普通用户配置困难 | 线性向导、推荐默认、高级折叠 |
| AI/向量环境不可用 | 基础搜索独立、确定性分析保底 |

## 7. 请确认

- **C17-1（推荐）**：采用 P0～P6 逐阶段闭环，不一次性大爆炸重写。
- **C17-2（推荐）**：每个阶段必须同时交付后端、前端、数据和验收证据。
- **C17-3（推荐）**：旧 API/入口在新路径验收后再按发布周期移除。
- **C17-4（推荐）**：功能开关和旧活动索引是主要回滚方式。
- **C17-5（待选择）**：确认后优先从 P1 已有实现收口，还是先补 P2 搜索？推荐先收口 P1，避免在不完整版本绑定上继续叠加搜索。
