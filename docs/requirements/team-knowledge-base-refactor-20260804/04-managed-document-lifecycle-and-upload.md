# 04 受管文档生命周期与上传确认

- 状态：Proposed
- 对应用户需求：3、7

## 1. 文档状态模型

```text
草稿 draft
  → 提交 committed
  → 解析/索引 processing
  → 可用 ready
  → 软删除 deleted
  → 恢复 restored（恢复原逻辑文档并重建派生索引）
```

解析失败是某个文档版本的处理状态，不等于丢失原始资产。正式版本不可修改；后续编辑产生新版本。

## 2. CRUD 语义

- 新增：人工 Markdown/富文本草稿，或上传自定义文件。
- 修改：只修改草稿；对已提交版本编辑时先从该版本创建新草稿。
- 查询：列表、详情、当前版本、历史版本、解析状态、来源和附件。
- 删除：普通删除为软删除，从新检索中排除但保留历史引用。
- 恢复：恢复逻辑文档并幂等重建缺失索引。
- 永久删除：独立高风险能力，默认不在普通页面提供。

## 3. 并发与冲突

草稿包含 `revision`。保存时必须携带上次读取的 revision；不一致则返回冲突、当前版本摘要和用户未提交内容，禁止最后写入覆盖。

## 4. 上传体验

1. 用户选择一个或多个文件。
2. Rust 返回受控文件句柄和识别摘要，前端不长期保存绝对路径。
3. 系统自动推断标题和文档类型，继承项目/版本。
4. 用户只确认差异项后提交。
5. 立即创建任务，显示逐文件排队、处理中、成功、部分成功、失败或取消。

## 5. 当前可复用实现

- schema v39 已包含资产、草稿、版本绑定、解析产物和上传记录。
- 分域文档 Command/API 已覆盖草稿保存、提交、恢复到草稿、删除预览和恢复。
- 新增文档页面已支持手工草稿和文件选择/上传。
- 仍需补齐文档目录、详情编辑、历史比较、删除/恢复页面和真实文件闭环。

## 6. 验收标准

- 保存失败、返回上一步或关闭对话框不丢输入和已选文件。
- 同一草稿并发编辑不会静默覆盖。
- 已删除文档不进入新搜索/问答，但历史引用仍可解释。
- 上传文件复制失败时，数据库记录和引用计数回滚一致。
- 永久删除前显示资产、版本、索引和引用影响。

## 7. 请确认

- **C04-1（推荐）**：所有正式内容变化都生成不可变文档版本。
- **C04-2（推荐）**：普通删除统一软删除；永久删除只在高级管理入口开放。
- **C04-3（推荐）**：草稿使用乐观并发控制，冲突必须人工处理。
- **C04-4（推荐）**：上传原文件进入内容寻址资产区，SQLite 只保存存储键和元数据。
- **C04-5（待选择）**：首期人工编辑器采用 Markdown，还是同时提供富文本？推荐先 Markdown + 预览，富文本后续评估。
