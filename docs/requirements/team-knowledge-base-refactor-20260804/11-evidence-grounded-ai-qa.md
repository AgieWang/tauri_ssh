# 11 基于证据的 AI 问答确认

- 状态：Proposed
- 对应用户需求：10

## 1. 问答管线

```text
用户问题
  → 解析项目/版本/仓库范围
  → 标题 + 全文 + 可选向量 + 已确认图谱召回
  → 权限、敏感度、版本和状态硬过滤
  → 去重、融合和上下文预算
  → Chat Provider 生成回答
  → 主张-引用校验
  → 返回答案、引用、冲突和缺口
```

范围有歧义时先返回候选项目/版本并停止，不让模型猜测。

## 2. 回答结构

- 当前回答范围。
- 结论摘要。
- 需求/设计与实现证据。
- 测试或运行证据。
- 风险、冲突、缺失和未知项。
- 可打开引用。
- 如选择跨版本比较，单独展示后续演进。

## 3. 证据规则

- 项目内部事实必须有引用。
- 引用需包含项目、版本、文档版本或仓库 Commit、位置和内容哈希。
- 文档互相冲突时并列展示，不由模型擅自选真。
- 证据不足时回答“现有知识库无法确认”，并建议补充什么材料。
- 模型常识可用于解释通用概念，但不得补写内部事实。

## 4. Provider 规则

- 只展示具有 chat 能力的 Provider；Embedding-only 不进入问答选项。
- 默认继承系统推荐 Provider，普通用户不需要每次选择。
- 远程问答与远程 Embedding 分开授权。
- 发送前支持高级“预览证据上下文”，但默认不展示冗长技术配置。

## 5. 会话与审计

首期保存问题、范围、引用 ID、Provider/模型、回答摘要和结果状态；不保存秘密或完整敏感上下文。是否持久化多轮对话全文由用户确认。

## 6. 当前状态

旧实现已有问答、上下文预览和混合检索基础；新 `qa` 分域仍是骨架。必须重新接入新文档版本、版本清单、标题检索、图谱投影和引用校验，并完成真实有证据/无证据/冲突测试。

## 7. 验收标准

- 使用具体 API/类名和自然语言问题都能返回正确版本引用。
- 检索通道均为 0 时明确是证据缺口，不伪装模型故障或生成无引用答案。
- 查询旧版本不泄漏新版本内容。
- 引用点击能打开精确文档章节、Office 位置或 Git 文件位置。
- 敏感片段在上下文、回答、日志和审计中均被阻断或脱敏。

## 8. 请确认

- **C11-1（推荐）**：默认 evidence-only，内部事实必须引用。
- **C11-2（推荐）**：范围歧义先澄清，禁止模型猜项目或版本。
- **C11-3（推荐）**：证据不足明确拒答并给出补充建议。
- **C11-4（推荐）**：Provider 默认自动选择有 chat 能力的推荐项，高级设置可改。
- **C11-5（待选择）**：是否默认持久化多轮问答全文？推荐仅保存会话元数据和用户主动收藏的问答，降低敏感数据沉积。
