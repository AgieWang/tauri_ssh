# 07 自定义文档版本管理确认

- 状态：Proposed
- 对应用户需求：7

## 1. 两层版本

- 项目版本：多个仓库在某时点的代码与来源范围。
- 文档版本：一份逻辑文档每次提交形成的不可变内容版本。

文档版本可绑定一个项目版本，也可明确标记为“跨版本共享”。未绑定状态必须可见，不得自动归入最新版本。

## 2. 提交模型

```text
逻辑文档
  ├─ 草稿 revision 1..N（可变）
  └─ 提交版本 v1 → v2 → v3（不可变父子链）
                  └─ 与项目版本/仓库快照的绑定
```

提交时保存标题、正文/资产哈希、父版本、提交说明、提交者标签、解析器版本、创建时间和项目版本绑定。

## 3. 恢复与比较

- 恢复历史不会改写当前版本；系统从历史版本创建新草稿，再由用户提交新版本。
- Markdown/文本提供逐行差异。
- Office 提供解析文本/结构差异、资产哈希、工作表或页码变化。
- 解析器版本变化应与内容变化分开显示。

## 4. 状态与检索

- 草稿不进入正式搜索、向量、图谱或问答。
- 提交成功后创建幂等解析/索引任务。
- 绑定不完整或解析失败时，文档保留但明确标记为不可完整检索。
- 跨版本共享文档必须由用户显式选择，并在回答引用中标记。

## 5. 当前状态

- 草稿、父版本、提交、恢复到草稿和版本绑定表已经存在。
- 新建文档页面已能保存草稿，但完整编辑、提交、历史、比较、版本绑定体验仍需收口。

## 6. 验收标准

- 两名编辑者基于不同 revision 保存时触发冲突。
- 从 v1 恢复后创建 v4，不修改 v1/v3。
- 未绑定文档不会出现在某历史版本的默认搜索中。
- 跨版本文档在结果和引用中有清晰标识。
- Office 文件更新可看到资产和解析结构差异。

## 7. 请确认

- **C07-1（推荐）**：提交版本不可变；历史恢复始终创建新草稿/新版本。
- **C07-2（推荐）**：未绑定文档不自动归入最新项目版本。
- **C07-3（推荐）**：草稿不参与正式检索和问答。
- **C07-4（推荐）**：允许显式“跨版本共享”，默认关闭。
- **C07-5（待选择）**：提交说明是否强制？推荐首期可选，但恢复、跨版本共享和 AI 分析确认时强制填写。
