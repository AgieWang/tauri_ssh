# 15 线性 UX、普通用户体验与中文文案确认

- 状态：Proposed
- 对应用户需求：11

## 1. 设计原则

- 一次只让用户做一个主要决定。
- 默认值来自上下文、检测结果或安全推荐。
- 技术参数放入“高级设置/查看详情”，不在主流程堆文字。
- 主操作使用动词和业务结果，如“创建项目”“开始处理”“确认入库”。
- 状态说明回答三个问题：正在做什么、结果是什么、下一步是什么。

## 2. 字段分级

| 分级 | 定义 | 示例 |
|---|---|---|
| 必填 | 无法安全推断 | 项目名称、问题文本 |
| 推荐默认 | 系统可安全选择 | 默认分支、当前项目/版本、本地向量 |
| 按需确认 | 仅异常时展示 | 某仓库缺少 Tag、格式识别冲突 |
| 高级设置 | 低频技术项 | Commit SHA、维度、分块、关系深度 |

## 3. 术语表

| 技术术语 | 默认中文展示 |
|---|---|
| Repository | 代码仓库 |
| Release/Manifest | 项目版本/版本清单 |
| Embedding Profile | 向量方案 |
| Chunk | 内容片段 |
| Code Symbol | 代码元素 |
| Fingerprint | 配置标识（详情中显示原文） |
| Checkpoint | 处理进度点 |
| Evidence only | 只根据知识库证据回答 |

内部枚举/API/数据库值保持稳定，只修改展示标签。

## 4. 反馈规范

- 立即反馈：点击“捕获/分析/同步/上传”后 100ms 内进入 loading 或创建任务。
- 防重复：提交中禁用同一主操作；后端幂等兜底。
- 成功：显示完成内容和直接下一步，不只显示“成功”。
- 部分成功：展示成功/失败数量和逐项重试。
- 失败：显示业务原因、保留输入、提供重试/返回/查看详情。
- 无变更：明确显示“没有发现需要更新的内容”，不显示误导性的 `0/?`。

## 5. 页面密度

- 项目概览只展示准备情况、风险和 1～3 个下一步。
- 搜索默认一个输入框和当前范围。
- 文档新增先选择“新写内容/上传文件”。
- 图谱默认一层关系，不展示全量网络。
- 问答默认隐藏 Provider、TopK、上下文预算等参数。

## 6. 可访问性与桌面适配

所有表单有可见 label；图标按钮有 Tooltip/可访问名称；危险操作二次确认；Modal/Drawer 输入时防遮罩误关；键盘可完成主流程。分别验证最小、常用和大窗口，明确滚动区域。

## 7. 浏览器验收任务

1. 新用户从空状态创建多仓库项目。
2. 返回上一步后数据保留。
3. 上传合法、损坏和超限文件。
4. 搜索无结果、降级和打开引用。
5. 分析中重复点击、失败、重试和草稿确认。
6. 问答有证据、无证据和版本歧义。
7. 控制台无未处理错误，页面无不可达内容。

## 8. 请确认

- **C15-1（推荐）**：默认流程只展示必填和推荐默认字段。
- **C15-2（推荐）**：新/改下拉、单选、多选、菜单和状态统一中文展示。
- **C15-3（推荐）**：所有异步动作显式反馈并防重复提交。
- **C15-4（推荐）**：高级技术原文保留在详情，不从系统中删除。
- **C15-5（待选择）**：是否需要“专家模式”一次展示全部配置？推荐首期不单独建设，使用逐页高级设置即可。
