# 00 需求基线与范围确认

- 状态：Proposed
- 对应用户需求：全部 11 项

## 1. 产品目标

建设一个面向普通用户也能完成配置和检索的项目知识工作台，统一管理代码仓库、项目文档、人工知识、版本、图谱、向量与 AI 问答，并保证每条重要结论能够回到项目、版本、文档或代码证据。

## 2. 核心业务对象

```text
知识项目
  ├─ 多个 Git 仓库绑定
  ├─ 多个项目版本（每个版本含多仓库 Commit 清单）
  ├─ 多个逻辑文档
  │    └─ 多个不可变文档版本
  ├─ 搜索索引、向量索引和图谱投影
  └─ 分析任务、问答记录与审计证据
```

## 3. 用户角色

| 角色 | 默认权限 | 主要任务 |
|---|---|---|
| 项目维护者 | 创建项目、关联仓库、配置版本、提交文档 | 建立和维护项目知识范围 |
| 内容编辑者 | 新增、编辑、提交、上传、恢复文档 | 维护可追溯知识内容 |
| 普通使用者 | 搜索、查看文档/图谱、发起问答 | 获取有引用的项目知识 |
| 管理者 | Provider、向量、配额、安全、评测 | 管理能力开关和发布门禁 |

首期不建设中心化账号和实时协作服务，权限先依赖桌面应用本地用户、已有安全凭据和项目级授权上下文；未来多人协作另立需求。

## 4. 功能范围

- 项目 CRUD 与多 Git 仓库关联。
- Markdown、文本、HTML、现代 Office、PDF 文本层、图片资产与可选 OCR。
- 人工文档和上传文档的草稿、提交、查询、软删除、恢复及版本管理。
- 标题、全文、可选向量和图谱增强搜索。
- 分支、Tag、Commit 形成的多仓库项目版本清单。
- AI 只读代码分析、草稿审核和确认入库。
- 版本化知识图谱、本地/远程向量化和本地向量存储。
- 基于证据的 AI 问答、拒答、冲突提示和引用打开。
- 持久化任务、审计、质量评测和阶段开关。

## 5. 明确非目标

- 不建设在线 Office 编辑器、远程向量数据库或中心化知识 SaaS。
- 不执行仓库代码、构建、测试、Hook、宏或脚本。
- 不允许 AI 自动发布正式知识或自动确认关系。
- 不承诺首期解析旧版二进制 Office 的全部特性。
- 不把构建、单测或页面截图等同于真实接入/RAG 验收。
- 不通过清库、删除旧表或重写历史版本完成重构。

## 6. 成功标准

1. 普通用户能在不理解内部 ID、Commit SHA、维度等术语的情况下完成项目创建、仓库选择、版本创建和文档上传。
2. 搜索在没有任何 AI/向量模型时仍可使用标题与全文通道。
3. 历史版本查询不会混入后续版本证据。
4. AI 分析文档和回答均有可打开引用，证据不足时明确停止。
5. 远程发送默认关闭，敏感内容、凭据和未授权路径不会外发。
6. 迁移保留现有数据，失败可恢复到旧入口或旧活动索引。

## 7. 当前证据与差距

- 当前代码迁移版本为 schema v39，已有项目、仓库绑定、版本清单、资产、草稿、上传、图谱表、标题索引等结构。
- 当前新路由已具备项目列表、项目设置、概览和新增文档页面。
- 搜索、分析、图谱、问答等分域模块中仍有占位或兼容导出，不能视为全部重构完成。
- 本文档只确认目标产品，不确认现有代码已经达到目标。

## 8. 请确认

- **C00-1（推荐）**：首期定位为本地优先桌面知识平台，不建设中心化多人协作服务。
- **C00-2（推荐）**：AI 仅能生成草稿或回答，不直接改变正式知识事实。
- **C00-3（推荐）**：项目、版本和证据引用是所有检索/问答的强制范围。
- **C00-4（推荐）**：现有数据和 API 采用兼容迁移，不清库、不一次性重写。
