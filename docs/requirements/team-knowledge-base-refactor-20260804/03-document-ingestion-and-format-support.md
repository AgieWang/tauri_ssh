# 03 文档接入与格式支持确认

- 状态：Proposed
- 对应用户需求：2、3

## 1. 统一接入流水线

```text
用户选择文件/仓库发现文件
  → Rust 路径与授权校验
  → 文件签名、MIME、扩展名和大小校验
  → 复制到内容寻址资产区
  → 解析器注册表选择适配器
  → 结构块、文本、附件、质量和警告
  → 文档版本与项目版本绑定
  → FTS/向量/图谱派生任务
```

## 2. 首期格式矩阵

| 格式 | 首期能力 | 明确限制 |
|---|---|---|
| Markdown/MDX/TXT/LOG/JSON/YAML/SQL | 文本、标题、代码块、行号 | 编码失败需可见 |
| HTML/HTM 原型 | 清洗后可见文本、控件标签、相对资源 | 不执行脚本，不加载外网资源 |
| DOCX | 标题、段落、列表、表格、图片引用 | 不执行宏，不保证嵌入对象 |
| XLSX | 工作表、单元格、表格、命名区域、公式文本/缓存值 | 不计算公式 |
| PPTX | 幻灯片文本、备注、表格、图片引用、页码 | 动画与复杂对象可警告 |
| PDF | 文本层和扫描页识别 | 扫描页无 OCR 时只标记待处理 |
| PNG/JPEG/WebP/GIF/SVG | 元数据、受控预览、可选 OCR | SVG 清洗；无 OCR 不声称有全文 |
| DOC/XLS/PPT | 可选隔离转换器 | 未配置时明确“不支持”，禁止执行宏 |

## 3. 当前实现状态

- Markdown/文本系列已有解析基础。
- HTML、DOCX、XLSX、PPTX 和 PDF 文本层在当前任务清单中已标记实现，但仍需恶意文件、损坏、超限和真实夹具验收。
- 图片 OCR、旧版 Office 转换器和完整批量失败验证仍待实施。

## 4. 默认限制建议

| 项目 | 推荐默认值 |
|---|---:|
| 单文件 | 20 MiB |
| 单批文件数 | 50 |
| 单批原始总量 | 100 MiB |
| OOXML 条目数 | 2,000 |
| 展开总量 | 200 MiB |
| 嵌套压缩 | 深度 1，默认拒绝内部压缩容器 |
| 单文件解析 | 30 秒 |
| 单项目受管资产 | 2 GiB，80% 提醒 |

这些值必须配置化，可下调；放宽需要新的性能与安全证据。

## 5. 解析结果契约

每次解析返回 `parserId/parserVersion`、内容哈希、结构块、稳定位置、质量等级、警告和失败原因。部分解析不得伪装为完全成功；只有成功且允许公开的提交版本进入正式索引。

## 6. 验收用例

- 中文文件名、长标题、表格、幻灯片、HTML 控件和相对图片引用。
- 损坏文件、错误扩展名、加密 Office、压缩炸弹、超大 DOM、脚本/事件属性、SVG 外链。
- PDF 无文本层、图片无 OCR、部分解析和用户取消。
- 批量中个别失败可逐项重试，临时文件能清理。

## 7. 请确认

- **C03-1（推荐）**：首期原生支持现代 OOXML、HTML、PDF 文本层和图片元数据。
- **C03-2（推荐）**：旧版 DOC/XLS/PPT 没有安全转换器时明确拒绝，不做静默降级。
- **C03-3（推荐）**：本地 OCR 按需启用；无 OCR 时图片仍可按标题/元数据搜索。
- **C03-4（推荐）**：远程视觉/OCR 与远程问答、Embedding 分开授权。
- **C03-5（待选择）**：是否接受上述首期大小/数量/配额默认值？
