# 08 AI 代码分析与人工审核确认

- 状态：Proposed
- 对应用户需求：5

## 1. 核心原则

AI 不直接扫描当前工作区并发布知识。分析固定在项目版本清单和各仓库 Commit 上，先产生确定性静态证据，再将获准的最小证据发送给具备分析/对话能力的 Provider。

## 2. 分析流程

```text
选择项目版本
  → 解析多仓库 Commit 清单
  → 只读遍历 Git 对象（不 checkout）
  → 提取文件、代码元素、API/IPC、SQL、配置和测试证据
  → 敏感检测与上下文预览
  → AI 生成有引用草稿
  → 引用校验和事实/解释分区
  → 用户查看、编辑、比较
  → 确认后提交正式文档版本
```

## 3. 分析产物

- 仓库和模块概览。
- 系统入口、API/IPC、数据库对象和主要调用关系。
- 配置、测试、风险和未确认项。
- 每个主张引用仓库、Commit、路径和稳定位置。
- 分析器质量等级：AST、结构化降级、纯文本、跳过。

界面统一使用“代码元素”，避免无解释地显示“符号”。

## 4. 安全边界

- 不执行代码、构建、测试、Hook、脚本或二进制。
- Git 路径使用 NUL 分隔遍历和原始字节安全解码，覆盖中文路径。
- 排除规则在读取前应用；敏感文件默认只记录路径、哈希和阻断原因。
- 远程分析需要系统、来源、文档/内容和 Provider 四层授权。
- 失败不自动改用其他远程 Provider。

## 5. 交互规则

- 点击后立即显示“正在读取快照/正在分析/等待审核/失败”。
- 分析中禁用重复提交，同一范围用幂等键去重。
- 允许查看已纳入和已跳过范围。
- AI 原始草稿和人工编辑差异永久保留。
- 无效引用或无证据主张阻止确认入库。

## 6. 当前状态

旧知识模块已有源码快照、文件、代码元素、关系和分析基础；新分域 `analysis` 目前主要是骨架/兼容出口。需要重构快照读取、运行冻结、草稿审核、引用校验和新 UI，不能把旧分析按钮视为新流程完成。

## 7. 验收标准

- 对 4 个仓库的 Tag 快照分析时不改变任何工作树。
- 中文及转义路径、`.codex/**` 排除、二进制和敏感文件行为正确。
- 分析失败后显示失败阶段和可重试操作，不留下“已完成”假状态。
- 用户编辑确认后的文档可按标题/全文搜索并打开源引用。
- Embedding-only Provider 不出现在分析/问答模型选项中。

## 8. 请确认

- **C08-1（推荐）**：固定 Commit 的静态证据先于 AI 分析。
- **C08-2（推荐）**：AI 仅生成草稿，人工确认后才进入正式知识库。
- **C08-3（推荐）**：无有效引用的项目事实阻止入库。
- **C08-4（推荐）**：默认分析当前项目版本的全部启用仓库，允许高级范围缩小。
- **C08-5（待选择）**：是否允许纯本地确定性分析在无 AI 时直接提交？推荐允许，但文档标记为“静态分析报告”。
