# AI 全能工作站原型生成 Brief：Tauri SSH

## 目标

为 Tauri SSH 设计一套现代简约风格的桌面应用原型图。产品是 AI 时代的 SSH 运维工具，参考本机 Reeve App 的受控运维体验：服务器清单、AI 策略、审批队列、脱敏凭据、MCP 工具、SFTP、审计。

原型覆盖率要求：100%。必须覆盖需求文档中的所有 V0.1 页面、关键弹窗、空状态、风险状态和设置页。

## 设计风格

- 现代简约、专业、克制，适合长期运维工作台使用。
- 避免营销风、插画风、夸张渐变和大面积装饰。
- 主色建议：深墨绿 / 青绿色作为操作强调，灰白背景，红/橙用于风险和审批。
- 桌面应用优先：密度适中，信息可扫描，侧边栏 + 顶栏 + 工作区布局。
- 卡片圆角不超过 8px，工具栏和表格保持紧凑。
- 图标优先使用 lucide 风格线性图标。

## 需要生成的页面

1. 启动/欢迎页
   - 选择“导入 ~/.ssh/config”“手动新增服务器”“连接 JumpServer/堡垒机会话”“启用 MCP Server”。

2. 工作台 Dashboard
   - 服务器健康摘要、最近连接、待审批命令、风险事件、传输队列、AI 建议。

3. 服务器管理
   - 左侧分组树，右侧服务器表格。
   - 支持标签、环境、AI 策略、来源筛选。
   - 来源包括 manual、ssh_config、jumpserver。

4. 新增/编辑服务器抽屉
   - Host、端口、用户名、认证方式、默认路径、标签、环境、AI 策略、允许路径。
   - 凭据字段必须显示为加密/脱敏状态。

5. ~/.ssh/config 导入向导
   - 文件扫描、解析结果预览、逐项选择、冲突处理、导入总结。

6. 凭据保险库
   - 密码、私钥、AI Provider Key 的加密条目。
   - 展示“不可见明文”“测试”“轮换”“删除”“复制需系统授权”。

7. 终端工作区
   - 多标签终端、服务器上下文、连接状态。
   - 右侧 AI 助手：解释输出、建议命令、申请执行。
   - 建议命令卡片要显示风险等级、策略结果和执行按钮。

8. 命令审批队列
   - 待审批、已允许、已拒绝。
   - 展示 actor、服务器、命令、风险等级、AI 理由、允许一次/拒绝/允许同类 10 分钟。

9. SFTP 文件管理
   - 远程目录树、文件表格、路径栏、上传下载操作。
   - 下方传输队列。
   - 权限保护提示。

10. 内置文本编辑器
    - 文件标签、编码、换行符、保存/另存为/差异预览。
    - 保存前审批提示，冲突检测。

11. AI Provider 设置
    - OpenAI API、DeepSeek、GLM、Kimi、MiniMax、自定义 OpenAI-compatible Endpoint。
    - API Key 加密保存，连接测试，模型名、Base URL、温度、超时。

12. MCP Server 设置
    - 开关、监听地址、客户端配置示例、工具列表。
    - 工具级权限策略：list_servers、system_info、ssh_exec、sftp_list、sftp_read、sftp_write、tail_log。

13. MCP 工具策略详情
    - 每个工具的只读/需确认/审批/禁止策略。
    - 绑定服务器分组和风险等级。

14. JumpServer/堡垒机会话兼容页
    - 明确“不获取明文凭据”。
    - 支持嵌入 Web SSH、授权资产同步、连接令牌/网关模式预留。

15. 审计日志
    - 筛选条件：时间、服务器、actor、风险、审批状态、动作类型。
    - 明细抽屉：命令、输出摘要、脱敏字段、MCP 调用参数、审批链路。

16. 团队/工作区预留
    - 本地个人空间、成员字段预留、角色预留、审计 actor。
    - 标注 V0.1 只预留，不做云协作。

17. 系统设置
    - 安全、SQLite 加密、Keychain/主密码方案、跨平台 macOS/Windows 检查。
    - 主题、更新、日志、数据备份。

18. 空状态和错误状态
    - 无服务器、连接失败、AI Provider Key 未配置、MCP Server 未启动、审批被拒、危险命令被拦截。

## 关键交互

- AI 建议命令不能默认执行，必须经过策略或用户确认。
- 危险命令必须显示硬拦截，不允许执行。
- 凭据和 API Key 全程脱敏，不出现明文。
- MCP 调用要与 UI 操作共享审批和审计。
- JumpServer 集成只获取连接能力，不获取浏览器 Cookie 或目标服务器明文凭据。

## 页面文案风格

- 简洁、直接、偏运维专业。
- 示例命令和状态要真实可信。
- 风险提示要明确说明“为什么被拦截”和“可替代方案”。

## 输出要求

- 输出完整页面原型，不只输出一两个主页面。
- 每个页面都要体现可用状态，不要只有空白占位。
- 附覆盖矩阵，说明每个 PRD 功能对应哪个页面。
