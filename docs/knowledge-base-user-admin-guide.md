# 团队知识库使用与管理指南

本文档说明团队知识库的本地优先使用方式。知识索引、FTS 和向量均保存在当前 Tauri SSH 客户端的 SQLite 数据库中；首期不部署服务器向量数据库。Git、禅道和本地源码始终是可回查的事实来源。

## 使用前提

- 在“团队知识库”中先创建知识项目；项目别名用于识别提问中的项目名称。
- 为项目登记发布版本，并明确 Tag、分支或基线 Commit。无法确认归属的内容必须使用 `unversioned`，不能自动放入最新版本。
- 远程模型默认关闭。只有系统设置、来源设置和文档敏感级别都允许时，内容才能发送到远程 Embedding 或聊天 Provider。

## 导入文档与经验

在“来源与同步”新建来源，可选 Git 工作区、本地目录、单文件、手工 Markdown 或既有 AI 经验。

1. 填写稳定的来源标识与展示名称。
2. 对本地来源填写授权根目录；先执行“预览有效读取范围”，检查排除条目、符号链接、超大文件和敏感文件提示。
3. 配置包含/排除规则后保存并启动同步任务。
4. 在文档页按项目、版本和关键字核查导入结果、历史版本、分块和引用。

同步只读取已授权的内容。路径越界、符号链接逃逸、二进制、秘密或受限内容会被跳过；正文不会提供给前端、MCP 或远程 Provider。

## 本地模型与索引

“Embedding 索引”支持 FTS-only、本地向量与经授权的远程向量模式。

- 本地模型必须显式离线导入（模型目录与 SHA-256）或从管理员配置的内部镜像下载。模型包还必须在 `runtime/` 下携带当前平台的 ONNX Runtime（Windows 为 `onnxruntime.dll`、macOS 为 `libonnxruntime.dylib`、Linux 为 `libonnxruntime.so`）；运行时与模型同受目录 SHA-256 校验，浏览器和桌面都不能传入任意下载地址。
- 创建 Profile 后先进行“模型测试”，确认实际维度；默认建议使用已在 macOS 混合语料基准中通过的 `multilingual-e5-small-int8`，其他模型必须先完成相同的真实测试。模型、修订、维度、前缀、规范化或分块策略变化都会生成新的 Profile 指纹。
- 重建前查看影响片段、磁盘增量与远程字符数估算，并在确认后执行“重建 → 构建 → 校验 → 激活”。
- 当前活动索引会在蓝绿重建期间继续提供检索；若新索引失败，保留旧索引。可通过“回滚至此”切换回保留的已完成 Profile。
- 下载、导入或模型测试失败时不会自动改用远程 Provider。

## 禅道只读同步

1. 管理员先在安全凭据库保存 Token、Cookie 或密码引用；知识库仅保存引用键，不保存明文。
2. 默认填写 HTTPS 地址并保持“校验证书”开启。仅当确认目标为受控内网且无法提供 HTTPS 时，先在“安全 → 策略”把该主机精确加入 HTTP 域名白名单，再填写 HTTP 地址、显式启用“允许内网 HTTP（高风险）”并完成二次确认；HTTP 会明文传输 Token/Cookie，不能用于不受控网络。
3. 在“禅道同步”创建连接并执行只读能力探测。HTTP 例外仍受每次访问白名单复核、凭据同源、只读 GET、禁止重定向、连接级限流和脱敏审计约束。
4. 根据返回的能力矩阵和远程范围，创建“远程项目/执行 → 知识项目/发布版本”映射。
5. 仅同步已探测支持的实体，然后生成事实文档。

生成文档包含项目概览、版本需求基线、追踪矩阵、任务执行、测试质量、变更记录与开放风险。生成过程不调用大模型；所有实体、关系和快照时间均保留为引用。不同禅道版本与权限可支持的接口不同，未探测到的故事变更、工时、测试运行、构建或发布接口不会被臆测调用。

## Git 与本地源码知识

- 仅登记已有 Git 工作区或用户授权的非 Git 目录；设置可分析语言、文件大小和未跟踪文件策略。
- Git Commit、Tag 与分支头通过对象读取和 Diff 建立不可变快照，不会 checkout、stash、reset 或切换分支。
- dirty 工作树与非 Git 目录均标注为非发布历史事实；捕获后再分析符号、调用、IPC/API、SQL 和测试关系。
- 使用代码快照、符号搜索、调用图、版本比较和影响分析查看证据。引用始终包含快照、相对路径与行号范围。

## 问答与引用核验

提问时优先选择项目与发布版本。系统先应用项目、版本、快照、来源和敏感级别硬过滤，再融合 FTS、活动 Profile 向量和已确认关系。

回答页面会显示引用、冲突和证据缺口。对于缺少实现或测试依据、资料冲突或版本范围不明确的问题，系统应说明证据不足，而不是补造内部事实。

## 恢复、清理与审计

- 任务异常关闭后会标记为 `interrupted`，可从安全检查点重试；取消会保留已完成的幂等批次。
- 删除知识来源、项目、连接或 Profile 使用软删除/禁用策略；不会删除原有 `ai_experiences` 数据。
- 清理本地模型缓存前确认模型未被重建任务使用；清理只影响当前客户端缓存。
- 高风险配置、远程批次、禅道访问、源码快照、关系确认和 RAG 引用会生成脱敏审计事件，不记录正文、密钥或 Token。

### 开发验收的本地 API 端口

开发版与已安装版本并行运行时，如默认 `127.0.0.1:17321` 已被占用，可为开发实例设置
`TAURI_SSH_LOCAL_API_ADDR=127.0.0.1:17322`，并在 Vite 开发环境设置
`VITE_TAURI_SSH_DEV_API_BASE_URL=http://127.0.0.1:17322/dev-api`。两个变量只接受回环地址；
生产构建忽略前端覆盖值。MCP 状态、浏览器 Dev API 和桌面命令仍共用同一 Service 与安全策略。

## 上线建议

按“目录与 FTS → 本地 Embedding → 混合 RAG → 禅道 → 源码分析 → MCP”分阶段启用。正式默认启用前，必须完成真实禅道只读同步、目标平台本地模型验证、桌面运行时验证和检索质量验收。
